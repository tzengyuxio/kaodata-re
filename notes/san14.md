## 封裝：0002/*.rdb ＋ *.rdb.bin*

- KT 引擎的 RDB：`.rdb` 是 `_DRK0000` 開頭的索引（+0x10 項數，+0x14 一個 KTID，+0x18 `data/`），接著是一筆筆 `IDRK0000` 項目：
  - +8 u64 項目大小、+0x10 u64、+0x18 u64 檔案大小。
  - +0x24 u32 檔案 KTID、+0x28 u32 型別 KTID、+0x2C u32 旗標。
  - 項目尾端的 ASCII 字串「偏移@大小」（十六進位）是資料在 `.rdb.bin` 裡的位置。
  - 沒有位置字串的項目（型別 0xBF6B52C7 等）是外部檔 `data/0x<KTID>.file`，下載裡大多沒有。
- `.rdb.bin` 裡同一位置又是一個 `IDRK` 標頭（大小＝項目大小 − 壓縮大小），後面是一串「u32 長度＋zlib」區塊。
- 位置字串可以接 `#N`，**N 是十六進位**，表示資料在分檔 `.rdb.bin<N 的十進位>`（`#e` 是 `bin14`、`#16` 是 `bin22`），沒有就是 `.rdb.bin`。
  - 先前當成十進位，才會有「`bin12` 不存在」「`bin16` 超出檔案」「主檔位置不對」這些解不出的 186 張。改成十六進位後 1767 張全部解得出來。
- KTID 是名稱的雜湊，沒有名稱表；項目在索引裡照 KTID 排序。

## ScreenLayout.rdb

- 18046 項：型別 0xAFBEC60C 的 `GT1G0600` 貼圖 8476 項、0xF20DE437 的 sprite 定義 8476 項、0x5599AA51 的 `LCSK` 版面 1085 項。
- sprite 定義：u32 sprite 數，每個 sprite 是 64 bytes 名稱＋UV 浮點數。名稱就是貼圖名，如 `face_0736_ctr`。
- **sprite 定義和貼圖在 `.rdb.bin` 裡緊接著存**：照（分檔, 偏移）排序後，每張貼圖後面接著的 sprite 定義就是它的名稱。7941 張這樣配得起來，其餘是沒有定義的貼圖。
- 貼圖：+0xC 表位置（0x20）、+0x10 張數；每張 8 bytes 標頭（+1 格式 0x5B＝BC3，+2 低、高 nibble 是 log2 寬、高，+7 bit 4 表示後面有擴充標頭），像素一般從 0x38 起。
- 頭像（`NNNN` 是頭像號）：

| 名稱 | 貼圖 | 張數 | 內容 |
| ---- | ---- | ---: | ---- |
| `face_NNNN_ctr` | 512×512 BC3 | 1467 | 小 |
| `face_NNNN_unique` | 1024×1024 BC3 | 1471 | 大 |
| `face_NNNN_a` | 2048×1024 BC3 | 1455 | 中：三個 636×900 sprite（`_a`、`_b`、`_c`） |
| `face_NNNNb_*` | 同上 | 18–19 | 0001、0002、0007、0009、0036（劉備）、0045（諸葛亮）、0060（曹操）、0064（孫権）等 19 人的第二張臉，用途未明 |

- `face_0001_ctr`、`face_0003_ctr` 一個檔放 512 與 1024 兩張，`face_0007b_a` 放三張 1024。
- 1767 張 512×512 的內容：`face_*_ctr` 1467、`face_*b_ctr` 18、道具 `sti_item*` 219、`sti_scenery_*` 25、`sti_advantage*` 10、其他 UI 約 25、沒有定義的 3 張。
- 有 `ctr` 的頭像號共 1468 個（0001、0003 那兩個算進去）。`face_0992_ctr`、`face_5012_ctr` 有定義，但配不到 512 貼圖。

## 劇本：0010_JP、0010_TC/*.s14

- `sceda??.s14` 是本體劇本，`scedaex??.s14` 是 PK 劇本，`fixdata*.s14` 是共用資料。
- 檔頭：u32 字串長度、`SN14SCN_VER0001`（PK 是 `SN14SCEXVER0001`）、UTF-16 的劇本說明，接著是 `LWC\x1a` 壓縮（同 `ls11.lwc_decode`）。
- DLC 劇本（`DLC/0010_*/`）、`DLC/DLCInfo??.s14`、`DLC/0011/gd_*.s14` 整檔加密：
  - 每 byte：`s = s * 0x6C078965 + 0x3039`，`w = s >> 16`，byte XOR `(w >> 8) ^ w` 的低 8 位。函式在 `SAN14PK.exe` RVA 0x32AA60（`.text` 要先照三國志13 的方法解 SteamStub）。
  - 種子每檔不同，同一劇本號的 `sceda`／`scedaex` 與各語言相同：09 0x124AFD、12 0x124B03、13 0x124B08、14 0x124B0A、16 0x124B0E、17 0x124B10、18 0x124B12、19 0x1332BD、29 0x15D7D5。種子表在哪還沒找。
  - `DLCInfoNN` 解開是「類型,號碼,群組」的 CSV，種子大多是 0x124AEA＋2N（24 是 0x1284C3、31 是 0x1284CC、34 是 0x1332CD，35 還沒解）。類型 3 是頭像號（如 08：5106–5145），類型 2 是 `gd_<號碼>.s14`（登錄武將，如 24：5101、5102、5105、5106；31：2001–2049）。
  - `gd_*.s14` 的種子還沒找到。

## 人物

- 每個劇本（本體、PK、DLC，日、繁中）都是同樣 1001 人，人物號 0–1000，照姓名讀音排序（0 是阿会喃，1000 是英布）。
- 人物表在 LWC 解開後的固定位置，記錄是緊密排列、不對齊的：

| 版本 | 表起點 | 記錄長 | 姓名位置 | 頭像號 |
| ---- | -----: | -----: | -------: | -----: |
| 日本體 | 0xA93A | 226 | +148 | +224 |
| 日 PK | 0xAC36 | 235 | +157 | +233 |
| 繁中本體 | 0xA982 | 298 | +148 | +296 |
| 繁中 PK | 0xAC7E | 307 | +157 | +305 |

  - +0 u16 人物號。頭像號是記錄最後的 u16。
  - 姓名區：姓 7 字、名 7 字、字 3 字（UTF-16LE，0 結尾補 0），接著是讀音：日文版是姓、名、字的片假名各 7 字；繁中版是 3 × 19 字的排序碼（如劉備 `01029`）。
  - 外字在 U+E000 起：日文 86 人（如陰夔寫成「陰」＋U+E09F），繁中 7 人（孔、司馬、周、朱、姚、羊、劉的某些名）。
- `scedaexce19.s14`（DLC）的人物表排法不同：記錄 244 bytes，姓名在 +166，頭像號在 +242；1001 人相同，只有 6 個同名者頭像號對調。
- 頭像號就是 `face_NNNN` 的號碼，人物號 ≠ 頭像號。一人一臉，所有劇本、本體與 PK 都一樣（`sceda71`／`scedaex71` 裡 1100 段的 200 人頭像號是 0，像是不登場）。
  - 用到的 1001 個：0–917 之間 801 個、1100–1299 共 200 個（阿貴、韋康、尹楷之類的小人物）。
  - 從人物資料看不出 PK 專用的臉：PK 劇本的 1001 人和頭像號與本體完全相同。
- 有 512 貼圖但沒有人物用的 467 個，看圖都是臉：497–994 間的零散號、1000–1037、1300–1309（古代人物、異民族、女性等）、2000–2166（新武將用）、2198–2199（剪影）、2500–2509、3000–3005、5000–5035（合作）、5100–5225（DLC 登錄武將，如光榮系合作角色）。
- 範例（人物號 → 頭像號）：張飛 655 → 1、関羽 146 → 2、呂布 986 → 3、趙雲 595 → 9、典韋 708 → 13、劉備 951 → 36、諸葛亮 439 → 45、曹操 520 → 60、孫権 552 → 64、貂蝉 639 → 566、阿貴 1 → 1100。
- 繁中名在 `0010_TC` 的同一張表，人物號相同（關羽、孫權、貂蟬）。
- `0001_*/msgdata.bin`、`msggame.bin` 是 `zp1`（同三國志13），解開是訊息字串表，人名只出現在台詞裡，不是人物表。

## 列傳（繁中）

- `0001_TC/msgdata.bin`（硬連結到 `games/san14pk-win/0001_TC/`）解開 `zp1` 後是封裝，第 0 項的第 0 項是一張 `XL` 字串表（5414 列，UTF-16LE，位置從 0x18 算）。第 386＋n 列是人物 n 的列傳，人物號同劇本的人物表（劉備 951：「漢之中山靖王劉勝之子孫……」）。日文版 `0001_JP` 排法相同。
- 和三國志13 同樣分三段：簡介、`\n^05<U+E020>^00` 之後是演義、`\n^03<U+E009>^00` 之後是正史（`^nn` 是顏色）。英布（1000）只有一段（`biography.san14_bios`，`dekoei.py biography san14pk-win`）。
- 列傳外字：U+E000 伷、E001 璝、E005 儁、E00C 喁（同名字）、E00B 崖（珠崖）、E030 坂（長坂坡）。E004 在羊衜與孫𩅦兩處都用（日文版孫𩅦有自己的外字 E06A），照「孫＋E004」換成 𩅦、其餘換成 衜。照上下文判定，沒有讀字型。🟡

## 匯出（`san14pk-win`）

- 遊戲目錄 `games/san14pk-win/` 是 `0002/ScreenLayout.rdb*` 與 `0010_JP`、`0010_TC` 的 `scedaex01.s14`（硬連結到 `games/steam/872410/`），以及 PK 的 27 個 `scedaex*.s14`（硬連結到 `games/steam/872410-pk/depot/`）。
- 1489 張 96×120（1470 個頭像號加 19 張 `b` 第二張臉，依頭像號排；`code` 是頭像號的 4 位大寫十六進位，`b` 臉沒有），逐張無損 WebP，共 27 MB：
  - BASE 是 636×900 的 `face_NNNN_a`。`_a`、`_b`、`_c` 三個 sprite 的 RGB 是同一張完整的畫（有背景，只差在 alpha），所以取 `_a` 的 RGB，不透明。
  - 框：每張 484×512 `face_NNNN_ctr` 在 636×900 上的框 (x, y, w, h)（`research/face-crop/san14_boxes.py` → `data/san14_boxes.json`，rmse 都 ≤ 26）。ctr 超出立繪邊緣的 0056、0127、0261、1102 改用 ctr 中段比對。
  - **4:5 裁切規則（使用者 2026-10-21 決定）**：高 S·h、寬 0.8·S·h、水平置中，上緣往下移掉的高度的 T：**(x + (w − 0.8·S·h)/2, y + T·(1 − S)·h, 0.8·S·h, S·h)，S = 0.554、T = 0.065**，和三國志12 的 96×120 對齊。
    - 依據（`research/face-crop/san14_vs_san12.py`）：三國志14 的立繪很多是三國志12 的 360×512 放大約 1.763 倍。兩邊同名的 578 人中，383 人的三國志12 大圖對得上三國志14 的立繪（rmse ≤ 25，同一張畫）。把三國志12 的 4:5 框（48×60 在 360×512 上的框）換到三國志14、再用 ctr 框表示：s 中位數 0.5544（四分位 0.5540–0.5549）、t 0.0654（0.0644–0.0661）、水平偏移 −0.0009 w（≈ 置中）。離群的 10 人是三國志12 那邊的框本身偏了。三國志12 沒有的人與三國志14 的新圖照同一組參數裁。
    - 之前的版本（同日，已取代）：S = 0.6（使用者從 `san14_rules.py` 的候選圖選的），T 先照三國志13 的眼睛高度（`eye_level.py`，Haar 眼睛偵測，295 張推回中位數 0.118）定成 0.12。和三國志12 比，臉占的比例偏小，使用者要求和三國志12 對齊。
  - Lanczos 縮成 96×120。立繪上的框寬 133–273 px，全部是縮小；框都在圖內。
- 立繪不是自己的 15 張，改從 1024×1024 `face_NNNN_unique` 裁（同一規則，ctr 在 unique 上的倍率都是 1.127）。unique 沒有背景，所以這 15 張保留透明：
  - 聯動 5000–5007、5100–5105：`_a/_b/_c` 指到同一張 2048×2048 的佔位貼圖（星空背景加一張曹操小卡），UV 是照 2048×1024 寫的，切出來是 636×1800。
  - 1023：`_a` 是另一個人，ctr 和 unique 是同一人。

  - 外字（U+E000 起）用另一個語言同一人的名字解開。兩邊都是外字的 4 個字照讀音與史書補（`SAN14PK_WIN_GAIJI`）：伷（孔伷、司馬伷、姚伷共用一碼）、喁（周喁）、衜（羊衜）、璝（劉璝）。三國志13 的 Big5 外字也有伷、璝。

### 格式

- **sprite 記錄的 +64 是貼圖號**：一個 `GT1G0600` 可以放多張貼圖（+0x10 張數，+0xC 位置表），`stand_*`、`0566_*`、`stl_event_p_*` 這類 atlas 要照 +64 取第幾張。`sango.san14_sprite` 只取第 0 張，頭像都是單張所以沒影響。
