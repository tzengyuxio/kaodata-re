# 水滸傳 天導108星（SUIKO2, Win 中文版）圖片與州地圖格式

`dekoei.py suikoden2-extras --game-dir ../games/suikoden2-win --out ../games/suikoden2-win/extract [--scenario 1-3] [--month 1-12]` 用到的格式。來源是 `~/game-library/_original/win/5.31_水滸傳天導108星_killpeople.rar`（`_original/win/suikoden2-win.txt`），解開放在 `games/suikoden2-win/`。主程式 `SUIKO2.EXE`（Win32 PE，imagebase 0x400000），下文位址是 VA。2026-11-15 第一輪解圖與州地圖，人物、劇本還沒看。

## 色盤與圖檔

- 色盤：`SUIKO2.EXE` 的資源 RT_RCDATA 117（檔案 offset 0x12F388，768 bytes），每色 3 bytes，順序是 B、R、G，色號不位移。色號 0 是綠色的去背色，輸出 PNG 時設成透明。RT_RCDATA 357 是另一組色盤，用途沒查。
- 圖檔（LS11）：每張是 `2a 38`、u16 寬、u16 高、8bpp 色號，和風雲再起相同（`notes/sanr.md`）。

| 資料夾 | 檔 | 張數 | 內容 |
|---|---|---:|---|
| `kao/` | `KAO.SK2` | 368 | 頭像 216×160，背景是色號 0，遊戲裡疊在 `KAOBACK` 上 |
| `kaoback/` | `KAOBACK.SK2` | 45 | 頭像背景風景 344×160 |
| `cg/` | `CG.SK2` | 22 | 1 是 130×100 的全國圖、2 是 260×200 標路名的全國圖（遼、陝西、河北、山東、京畿、淮南、江南等）；3–5、13 是 1024×768 劇情背景；14–17、21 是 640×480 |
| `event/`、`item/` | `EVENT.SK2`、`ITEM.SK2` | 19、49 | 沒有逐一辨認 |

## 表檔：IMAGE.SK2、BGIMAGE.SK2、PATSEQ.SK2

- `IMAGE.SK2`、`BGIMAGE.SK2`：u32 N，接 N+1 個 u32 offset，第 k 項（從 1 起）＝`data[off[k-1]:off[k]]`（0x4d69b0、0x4478f0）✅ code。
  - IMAGE 4006 個 sprite，輸出成 `sprites/NNNN.png`，hotspot 記在 `sprites/sprites.csv`（`x0`、`y0` 是 hotspot 到左上角的位移）。前段是田地、房屋、樹、動物、城門，後段多半是部隊動作。
  - BGIMAGE 79 張 64×64 的地面貼圖（`textures/`），草地、田地、沙地、水面、雪地等。
- sprite：s16 x0、s16 y0、u16 w、u16 h（外框），接著一串 {u16 len、s16 dx、s16 dy、len 個色號}；dx、dy 是相對前一段起點的位移，從 hotspot 開始；len＝0 結束 ✅ code。
- `BGPAT.SK2`：u16 40、u16 12，接 40 列 × 12 個 u16 貼圖號。列＝季節×10＋地面類別。
- `PATSEQ.SK2`：u32 offset[10]，每項是 u16 w、u16 h、w 列 × h 個 u16 sprite 號。第 1 項（69×24）是設施（載入到 0x533420），第 2 項（12×5）是樹與地面裝飾（0x530480），第 7 項是數字。
- `CMNDATA.SK2` 0x3D5A：41 州 × 226 bytes，+0 u16 州號，+2 州名（Big5，8 bytes）。州的寬度在州物件 +0x20（0x4b49b0），41 州都是 32。

## 州地圖（CHIKEI01–03.SK2）

三個檔推定對應三個劇本，彼此只差約 1130 bytes。

- 檔頭 0xC3 bytes 是參數表（0x460590 分 13 段讀入），和繪圖無關。
- 接著 41 筆，每筆 12112 bytes（0x4608f0）：u16 州號（1–41）、7 個 u16 州狀態值（0x462200 寫進州物件）、63 列 × 32 格 × 6 bytes ✅ code。奇數列只有 31 格（0x44c730）。

每格 6 bytes：

| byte | 意義 | 狀態 |
|---|---|---|
| b0 | 格子類別（0x460c90 依此建立不同 class）。地面類別：1→9、2→8、3→7、4→6、5→5、6→3、7→2、8→1（水）、10→4，其他→0；11–24 是 2×2 的設施地塊 | ✅ code |
| b1 | 低 4 bit 是高度，像素高＝(b1&0xF − 5)×15（0x449b60） | ✅ code |
| b2 | 類別 0 的地面貼圖用 b2/10 選（0x480830） | ✅ code |
| b3 | type 2 存到物件 +0x14；type 5、10 當州內清單索引 | 意義未知 |
| b4 | 4 時在左上鄰格建設施（0x461130）；設施地塊 4 格依序 2＝上、1＝左、3＝右、4＝下 | 位置是看資料推的【推】 |
| b5 | 1、3 的作用未知；2 呼叫 0x445b70(格, 1000)，推定是長滿的樹 | 🟡 |

繪圖步驟（`suikoden2_extras.render_map`，地面部分都照程式碼重寫）：

1. 頂點網格 65×65（0x448160），格 (c,r) 的中心頂點是 X＝2c+1+(r&1)、Y＝r+1。
2. 高度（0x449b60）：中心頂點取 b1 的高度，其他頂點取四鄰平均，邊界取三鄰，最後中心再平滑一次。
3. 明暗（0x449ae0）：由四鄰高差算法向量，光源 (1,1,1)/√3，分 0–11 級。
4. 貼圖（0x44aa30）：季節＝(月−1)//3（0x4587c0），BGPAT 列＝季節×10＋類別；類別 0 用 b2/10、類別 8（水）用欄 1、其他用明暗級。
5. 投影（0x44a6d0，視角 0）：(X×32, Y×16 − 高度)；另有 3 種旋轉視角沒做。
6. 三角形（0x44ab20、0x44af20）：每個中心頂點畫上下兩個三角形，Y 外層 X 內層；貼圖用平面掃描線，像素取 `tex[(螢幕y & 63)×64 + (x − 三角形最小 x)]`，貼圖號 0 填色號 0x40（0x449190）。
7. 物件（0x4d6f90、0x4d71c0）：sprite 的 hotspot 放在中心頂點的投影位置，依 Y×8 排序。設施取 PATSEQ 第 1 項的列 季節×17＋kind，4 層各取一張（0x4d9740）；地面裝飾（type 4）與樹取第 2 項（0x44bd00）。
8. 格線（0x44afd0，色號 0xEF）遊戲一定會畫，輸出不畫。

## 未解

- 頭像對應的人物：人物資料推定在 `SCEDAT0x.SK2`、`CMNDATA.SK2`，還沒看。
- 樹的種類 g（0 用 136、1 用 142）來自州所屬地方物件 +0x80 的 bit 3–4（0x4c4cb0），資料檔位置沒找到，輸出固定用 0。
- 設施 kind 0（城門 231／232／235／236）、kind 1、2 對應哪些格；type 2 格的 b4＝1–6（可能是橋或港）；b5＝1、3。
- 遊玩中的狀態沒畫：作物與林木生長、災害或旗標圖示（0x44c360）、天氣（0x44b250）、選取覆蓋層（+0xD14）。

## 負面結論

- 用平滑度在檔案裡掃描色盤：找不到，頭像是抖色的；色盤在 PE 資源 RT_RCDATA 117，要列資源才看得到。
- 以為 `IMAGE.SK2` 第 0 項是第二張 offset 表（hi/lo 拆開）、`BGIMAGE.SK2` 第 0 項是 245 bytes 的表：都是誤讀，兩檔開頭是 u32 N 和 N+1 個 offset，從 +4 起讀才對。
- 把 `CHIKEI` 當成從 0xD0 開始、每州後面接 16 bytes：起點錯了 3 bytes，那 16 bytes 其實是下一州的州號與狀態值。
- 把地面當菱形圖塊平鋪：不對，遊戲是有高度的三角網格加明暗選貼圖。
