# 大航海時代II（KOUKAI2, PC-98）頭像相關格式

`dekoei.py export koukai2-pc98` 用到的格式。來源是 `~/game-library/_original/pc98/[PC98] 大航海時代２.zip`（起動、A、B、C 四片 FDI），每片解在 `games/archives/pc98/disks/koukai2-pc98/`，遊戲檔（A–C）合併放在 `games/koukai2-pc98/`。`KOUKAI2.VER`：Mar.10.'93。`REL` 是 LHA 包（STAFF.TXT），和頭像無關。

- `MAIN.EXE` 沒有壓縮（MZ 檔頭 0x5000 bytes），下文的程式位址是映像（檔案 − 0x5000）位址。
- `DATA2.LZW`、`SNRDAT.LZW`、`SNRMES.LZW`、`EVENT.LZW` 是 LW11（`ls11.lw11_decode_files`），`DATA1.LZW`、`KAO.LZW` 是 LS11。

## 頭像與組合臉：KAO.LZW

- 和大航海時代外傳 Win 中文版的 `Monkao.dat` 逐 byte 相同，格式見 `notes/koukaigd.md`：LS11 的前 128 段是 64×80 頭像（byte k＝bit k），之後是 48×48 發現物圖；LS11 結束後（0x476A2）是 7 種類型 × 0x60C0 bytes 的組合臉零件。
- 畫法也相同（0x6EF8：上、下覆蓋，眼、鼻、口 OR），碼的 bit 14–15 不為 0 是組合臉（0x7069）。
- 類型（0x6FD0）是人物記錄 +0x31 的低 4 bit，跟著國籍：0 ポルトガル、1 イスパニア、2 オスマン帝国、3 イギリス、4 イタリア、5 オランダ、6 海賊（名稱是 `MAIN.EXE` 檔案 0x3A17F 的國名表）。所以每個航海士的臉型是固定的。
  - 外傳的類型是從艦隊記錄取（見 `notes/koukaigd.md`），本作 0x27F11 畫艦隊對手時也是用艦隊記錄 +0x15 的低 3 bit（0x715A）；隨機的路人臉是 `rand(7)`（0x6FF4）。

## 色盤

- `MAIN.EXE` 檔案 0x42BF8 起有好幾組 16 色（B、R、G 各 4 bit），前 8 色相同，數值也和外傳的相同。PC-98 以 v × 17 換算：`#000000 #0044dd #dd4400 #dd66aa #00aa66 #00aaff #ffaa66 #ffeedd`。

## 人物：DATA1.LZW 第 15 段

開局狀態（＝外傳的 `Sdata.dat`），`MAIN.EXE` 檔案 0x3ABEC 有一份前段相同的副本。`koei_games.load_koukai2_pc98_people` 讀三張表：

- 航海士：0x612 起 120 筆 × 50 bytes。+0 名 13 bytes、+13 姓 13 bytes（Shift-JIS），+26 u16 頭像碼，+49 低 4 bit 是類型。0–5 是六位主角（頭像 0–5），姓名匯出成「名・姓」。
- 事件人物：0x1D82 起 20 筆 × 22 bytes，名字 16 bytes，+18 是頭像（0x7185、0x71D1 讀 +0x12）：執事マルコ、モーリス伯…メルカトール（頭像 6–15）、各國國王與總督、ジュリアーノ教授、ウォルフ博士。
- 酒館女性：0x1F3A 起 30 筆 × 19 bytes，名字 12 bytes；頭像是 0x61＋序號（0x25F15：（記錄位址 − 表頭）／ 19 ＋ 0x61），和外傳相同。名字照原文（カルロ－タ 等的長音寫成全形減號）。

### 能力

- 航海士視窗（0x1BC30）顯示 7 項 統率力 航海術 知識 直感 勇気 剣技 魅力（標籤 DS:0x8C8），以及 年齢、航海レベル／経験、戦闘レベル／経験、国籍、技能。
- 記錄欄位：
  - +28–34：7 項能力
  - +42：年齢
  - +36、+38（u16）：航海Lv、航海経験
  - +37、+40（u16）：戦闘Lv、戦闘経験
  - +49 低 4 bit：国籍
  - +48：技能，bit 4–0 依序是 測量 地図作製 砲術 会計 交渉（`koei_stats.load_koukai2_pc98_stats`）
- ✅ code：例如ジョアン 78／75／73／85／82／82／89、18 歳、交渉；カタリーナ 航海Lv 8、戦闘Lv 10、砲術。
- 其他欄位（位址是 MAIN.EXE 解殼後 image）：
  - ✅ code +46 職位：DS:0x8A2＋2×職位 取名字（0x13547），1 提督 2 船長 3 副長 4 主計長 5 主席航海士 6 航海士，0 沒有職位。
  - ✅ code +44 所屬艦隊（艦隊表 133 bytes，0xFF 沒有，0x11D3C／0x11D4C），+45 所在港口（0x11D37）。
  - 🟡 +35 運：開新局時設成 rand(101)（0x15A71），之後當隨機加成用（0x9F01、0x1869E）；用法是 code，名稱是推定。
  - 🟡 +43 忠誠：0–100，在酒館請客會加（0x258A6，上限 100；超過 30 會說出自己最擅長的技能），不是 100 時每月變動（0x182B2）；用法是 code，名稱是推定。
  - ❌ +47：低 2 bit 是狀態，另有 0x10、0x40 旗標，意思未解。+49 的 bit 0x20 是可否雇用之類的旗標【推】。
- 指令：`dekoei.py koei-person koukai2-pc98`。

## 劇本裡的臉

`SNRDAT.LZW` 的 SNR0–6.DAT 是劇本腳本，`c0 0n cc <u16 頭像> c8 <u16 訊息號>` 以該頭像顯示 `SNRn.MES` 的訊息（MES 開頭是 u32 BE 的 offset 表）。沒有人物記錄的臉由說話者的 § 標籤與對白命名，歸「事件人物」：

| 頭像 | 名字 | 依據 |
|------|------|------|
| 18 | フェレロ公爵 | SNR1「§$s公爵§」（$s 是主角的姓，ジョアン篇是フェレロ） |
| 19 | フェレロ公爵夫人 | SNR1「§$s公爵婦人§」，SNR2／5／6「息子のジョアン」 |
| 21 | アルベルト皇太子 | SNR1 §標籤 |
| 22 | ファブリス・フェレロ | SNR2、SNR5 自報姓名 |
| 23 | マルティネス侯爵 | SNR1 §標籤 |
| 25 | エゼキエル | SNR1 §標籤、SNR3 自報姓名 |
| 59 | 手下 | SNR1、SNR2 挾持ルチア的手下（沒有名字） |
| 93 | シャイロック頭取 | SNR6 §標籤 |
| 94 | タファリ１世 | SNR1 §標籤 |
| 95 | メコンベ | SNR1 §標籤 |
| 96 | プレット・ペロー | SNR2 對白（「プレット・ペローって名前です」） |

- 92 沒有出現在任何腳本，歸「未使用」。
- `EVENT.LZW` 的 EVENT0–6.DAT 是圖，不是腳本。

## 港口、交易品、道具、地圖

`dekoei.py koukai2-extras --game-dir ../games/koukai2-pc98 --out ../games/koukai2-pc98/extract`（`koukai2_extras.py`）寫出 `tables/*.csv`（UTF-8-BOM）、`pictures/000–127.png`、`map/world.png`、`map/world_ports.png`。

本節位址：MAIN.EXE 的位址是解殼後 image（檔案 − 0x5000）；DS:0＝MAIN.EXE 檔案 0x39F00。表格位置寫的是 DATA1.LZW 第 15 段（開局狀態）的 offset，遊戲把它載到 DS:0xCEC，所以 DS 位址＝offset＋0xCEC。各表都有一個 far 存取函式（image 0x4F3A–0x4F9E），乘上記錄大小再加表頭。

名稱表（DS 的 near pointer 表，cp932）：交易品 0x7AE（46）、分類 0x814（10）、分類界線 0x80A（10 bytes：6 10 17 21 26 31 33 36 40 46）、酒 0x828（14）、酒價 0x844（14 bytes）、職位 0x8A4、國家 0x8B0（7）、發現物種類 0x924（8）、道具種類 0x934（14）。商圈名是 MESSAGE.DAT 第 0x181–0x18D 則（big-endian u16 offset 表，筆數＝第一個 offset／2）。

### 港口 0x52B0：130 筆 × 22 bytes（`ports.csv`）

0–99 是港口，100–129 是補給港（0x11FA3 迴圈 0x82 筆）。

| 欄位 | 內容 | 狀態 |
|------|------|------|
| +0、+2 u16 | 地圖 x、y（格） | ✅ code 0x24EA7；cross：130 個都落在世界地圖的港口格上（見下） |
| +4 | 名字 17 bytes | ✅ |
| +0x15 低 3 bit | 國家（0 ポルトガル … 5 オランダ，6 沒有） | ✅ code 0x239F3，同盟改寫 0x1890B |
| +0x15 bit 0x10 | 已發現：靠近時設定（0x3031C），港口清單只列有這個 bit 的（0x11F8F） | ✅ code |
| +0x15 bit 0x08 | 0x1892C 設定，經濟成長時權重加倍（0x29506） | 🟡 code |
| +0x15 bit 0x40 | 0x1C1BC 測試 | ❌ |

### 港口狀態 0x5DDC：100 筆 × 37 bytes（`ports.csv` 的後半）

| 欄位 | 內容 | 狀態 |
|------|------|------|
| +0 u16 | 經濟：交易所的貨物欄位、特產品要 等級×10 ≤ 經濟 才出現（0x23E83、0x265A2） | ✅ code |
| +2 u16 | 經濟累積值（上限 50000） | 🟡 code |
| +4、+6 u16 | 工業、工業累積值（0x294E8） | 🟡 code |
| +8–13 | 各國支持度（0x1742D、0x189AD） | 🟡 code |
| +14–23 | 10 個分類的價格率：價格＝基準×（率＋50）／100（0x1C16D、0x23A4D） | ✅ code |
| +24 u16、+26、+27 | 特產品基準價、特產品（0xFF 沒有）、出現所需等級（0x23A7F、0x24EC4、0x265A2） | ✅ code |
| +28 | 國內的區域 0–7（0x294EB） | 🟡 code |
| +29–32 | 道具店的道具（3 格，[0x5B7] 是 6–8 時 4 格，0x11FE3） | ✅ code |
| +33 | 商圈 0–12（0x24796） | ✅ code |
| +34、+35 | | ❌ |
| +36 | 酒館的酒（名 DS:0x828、價 DS:0x844，0x25392） | ✅ code |

- 不是玩家同盟港時買價再 ×1.2（0x239EF、0x23A8C）。

### 商圈 0x6C50：13 筆 × 128 bytes（`market_sell.csv`、`market_goods.csv`）

| 欄位 | 內容 | 狀態 |
|------|------|------|
| +0 | 46 個 u16：各交易品的賣價（0x1C1A5；0x24F7E 的傳聞找賣價最高的商圈） | ✅ code |
| +92 | 9 個 u16：各欄位的買價基準（0x23A5B） | ✅ code |
| +110 | 9 個交易品，0xFF 空（0x26604、0x23A2D） | ✅ code |
| +119 | 9 個等級，×10 和港口經濟比（0x23E83） | ✅ code |

- 交易品的分類用 DS:0x80A 的界線（0x239DB）✅ code。商圈 6、7 在 MESSAGE.DAT 都叫アメリカ（外傳分成中美、南美）。

### 船（`ships.csv`）

- 船種 0x5184：25 筆 × 12 bytes，資訊視窗 0x2A387（標籤 DS:0xB5E2）顯示的欄位都 ✅ code：+1 耐久（新船 ×9／10）、+2 旋回、+3 推進、+4 最大乘員／10、+5 必要水手、+6 u16 載貨量、+8 最大砲門。
- 🟡 +10 u16 價格基準（0x2A110 再乘亂數）；❌ +0、+9（+9 在 0x1A0A9、0x3076C 和乘員相乘）。
- 船隻 0x4BEE：22 bytes，0–39 是佔位（名字 "0"…"39"），40＋船種是造船所的樣本（0x2A3E1），名字就是船種名。+15 船種、+17 砲門、+18 u16 乘員、+20 u16 載貨量。

### 道具 0x75A4：100 筆 × 20 bytes（`items.csv`）

- +0 名 15 bytes、+0xF 圖（第 0x55＋n 張，0x28891）✅ code、+0x10 u16 價格 🟡（0x29191）、+0x12 威力 ✅ code（0x11412）、+0x13 低 4 bit 種類（DS:0x934，0x28873）✅ code，bit 0x10 是裝備中（執行時）。
- 說明在 ITEM.MES：100 筆 × 145 bytes。最後一筆「財宝20」的說明是開發者留言。

### 發現物（`discoveries.csv`）

- DATA2.LZW（LW11）裡的 COLONY.DAT：100 筆 × 177 bytes（0x33930 讀 index×0xB1）：+0 名、+15 圖（0x33994）✅ code、+16 說明。
- 位置表 0x72E8：100 筆 × 7 bytes。+0、+2 u16 x、y ✅ code（0x3033C）；+5 價值，知識增加 +5／10＋1 🟡 code（0x25E7C、0x2C944）；+6 低 3 bit 種類（訊息表 0x25E9D，名字取 DS:0x924）🟡，bit 0x40 是已發現（0x30374），0x80／0x20／0x10 也是執行時旗標；❌ +4（執行時和 0x5A 比較）。
- 98、99 是彩蛋（大航海時代／大航海時代Ⅱ），座標 (0,0)、(1,0)，不在地圖上。

### 圖（`pictures/`）

- KAO.LZW 第 128–255 段：48×48、3bpp planar（`genpei.decode_planar`），色盤同頭像。0–84 是發現物，85–127 是道具。✅ code

### 世界地圖 WORLDMAP.LZW（`map/`）

- 3 個 LS11 段，各 720×1080 格，左右接成 2160×1080。經度方向會繞回（0x2483A：(x＋0x7BD) mod 0x870）。
- 每段：1350 個 u16 區塊 offset（資料從 2700 起），30×45 個 24×24 格的區塊。
- 只有 1 byte 的區塊整塊同色：0xFD 海、0xFC 陸（bit 0：1＝海）。
- 其他區塊：
  - 第 1 byte 是底色（0x78–0x7D）：bit 2 是 1 時整塊是 bit 0；bit 2 是 0 時分兩半，bit 1＝0 左右分、1 上下分，前半（左／上）是 bit 0、後半相反。
  - 接著 18 bytes 的遮罩：12×12 個 2×2 小格，MSB 先、逐列。
  - 遮罩每個 1 對應一個 byte：小於 0x10 時 bit 3–0 依序是左上、右上、左下、右下（1＝陸）；0x10 以上是有代碼的陸地小格：0x10 港口、0x11 發現物、0x12 補給港。
- ✅ cross：港口表 130 個的座標都落在 0x10／0x12 小格上（地圖上正好 100＋30 個），發現物 98 個都落在 0x11 小格上（地圖上正好 98 個）；兩張表的座標各由程式讀（code），和地圖獨立對上。
- 🟡 底色「分兩半」和 0x10 以上當陸地：用海岸線長度判斷（全圖相鄰異色格數 90956 → 61530），畫出來的海岸線和實際地理一致。
- 【推】其他 0x10 以上的代碼（0x20、0xAF、0x6C–0x76 …，共 4405 格）分佈在山脈、沙漠邊緣，大概是地形；`world.png` 用深綠標出。
- 外傳的 Worldmap.lzw 和本作 byte 相同。

## 下一輪候選

- 地圖 0x10 以上的地形代碼 — 前置：找到地圖解碼與移動判定的程式（還沒找到；0x2483A 附近是座標換算）；做法：從 0x10／0x11 的判定往回追。
- 港口 +0x15 bit 0x40、港口狀態 +34／+35、船種 +0／+9、發現物位置 +4、航海士 +47 — 做法：追 0x1C1BC、0x1A0A9 等呼叫點，或在 DOSBox-X 改值看畫面。
- 船價、道具價的實際公式 — 做法：追 0x2A110、0x29191 的亂數與折扣。

## 負面結論

- 把地圖的 2×2 小格當成「相對底色翻轉」（XOR）：海岸線長度 98788，比絕對值（90956）差，不採用；底色 bit 1 當「小格位元反相」也比較差（92774）。
- 用「發現物落在海上」驗證地圖：舊的解法讓 98 個都落在海上，其實是把 0x11 的低 4 bit 當成陸海；改成代碼格之後才知道它們都在專用的小格上。
- IKKI.LZW 是 LW11 但檔名表是空的，`lw11_decode_files` 解不出；本節用不到，沒有再追。
