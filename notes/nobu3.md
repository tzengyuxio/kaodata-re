# 信長之野望・戰國群雄傳（NOBU3, DOS 中文版）頭像相關格式

`dekoei.py export nobu3-dos` 用到的格式。來源是 `games/archives/dos/信長之野望２_中文版_nobu2-c.rar`（台灣稱「信長之野望II」），解開放在 `games/nobu3-dos/`。

## 版本

- 英文 DOS 版 Nobunaga's Ambition II 的移植：`KAODATA.DAT`、`KAO_OE.DAT`、`PACKDATA.DAT`、`HEXDATA.DAT` 和英文版（`games/archives/dos/信長之野望２_英文版_nobunagas-ambition-ii.zip`）逐 byte 相同；劇本換成中文名字（1993-08）。
  - 英文版本身（MAIN.EXE 1990-12-10）的 SNDATA1／2 記錄排法、人數（240／212）和頭像碼也逐筆和中文版相同，只有人名是羅馬字（Uesugi Kenshin……）。同平台、同頭像、只有人名語言不同的在地化版本不另收（kaodata `docs/collection.md`），所以沒有英文版資料集。
- 中文版 `MAIN.EXE`（1993-11-04）是 TINYPROG 壓縮，開頭會印「Cracked by C.C.F. 4th November, 1993」，是破解版。用 unicorn 跑完解壓 stub 後，程式碼和英文版 `MAIN.EXE`（沒壓縮，MZ 檔頭 0x3E00，DGROUP 0x1DBC）相同結構。下文位址是英文版映像位址。
- `SAVEDATA.DAT`（2001）是玩家存檔，`SAVEDATA.ORG` 是空白存檔範本，都不用。

## 色盤

- 預設走 EGA mode 0x0E（640×200，0x1356），屬性表 DGROUP 0x3BDC `00 11 12 … 17`（0x12E6 int 10h AX=1002）；200 線模式下 0x1x 是加亮色。
- 顯示模式由 `MAIN.EXE` 的第一個參數決定（存到 [0xA882]）：英文版 `KOEI.COM` 偵測到 EGA／VGA 彩色就傳 `0`（mode 0x0E），CGA、MCGA、單色 EGA 傳 `1`（mode 6，640×200 雙色）。中文版的 `KOEI.COM` 換成不偵測顯示卡、不帶參數的小程式，所以只跑 EGA。
- mode 6 的頭像繪製在 0x285D（分派表 CS:0x94F，段基底 0x1CC0）：每 8 點的 3 bytes 只取第 3 個 byte（EGA 的 plane 1，綠色）寫進 B800，所以匯出的色號 bit 0 是 1 的（1 淺綠、3 黃、5 淺青、7 白）畫成白，其餘是黑；組合臉的 XOR／AND／OR 也只作用在這個 byte。匯出時另附這組 `mono` 色盤。
- 0x2668 把每 8 點的 byte 0／1／2 寫到 plane 0／2／1，和三國志II、大航海時代相同，所以是 `SAN2_PALETTE`。
- 頭像是 64×40 半高（200 線），匯出時每列重複一次（`san2_pixels`）。

## 頭像：KAODATA.DAT

- 0x0000–0x297BF：177 張 × 960 bytes（0x5832 `seek(code × 0x3C0)`）。
- 0x297C0 起：組合臉零件，4 組 × 0x1680 bytes。
- `KAO_OE.DAT` 是 KAODATA 第 0–27 張的複本，給武將編輯程式 `OE.EXE` 用，不匯出。

## 組合臉（0x588C）

- 頭像碼 bit 15 為 1 時是組合臉。人物記憶體 +0x23（檔案記錄 +0x21）。
- 零件（相對 0x297C0 的 offset、每筆大小、碼的欄位、半高列）：
  - 上：0x0000，0x1B0（18 列），bit 2–3，第 0–17 列
  - 下：0x06C0，0x210（22 列），bit 4–5，第 18–39 列
  - 眼：0x0F00，0x78（5 列），bit 6–7，第 13–17 列
  - 鼻：0x10E0，0x90（6 列），bit 8–9，第 18–23 列
  - 口：0x1320，0xD8（9 列），bit 10–11，第 24–32 列
- 上下直接複製，眼鼻口用 0x5866 逐 byte XOR 疊上，匯出用 `blend: "xor"`。照遊戲組法逐 byte 重算過全部 228 張組合臉，結果一致。
- 檔案裡有 4 組零件（髮型、背景不同），劇本的頭像碼 bit 0–1 也用到 0–3，但英文版和中文版的 MAIN.EXE 都只讀第 0 組（0x297C0 寫死），bit 0–1 沒有作用。匯出照 DOS 的實際畫面只放第 0 組（一個 variant）。其他 3 組可能是 PC-98 原版用的，沒驗證。
- code 是 bitfield，`$variant` 放在 bit 15、`base: 1`，讓網站產生的碼帶上組合臉旗標；bit 0–1 不解。

## 人物：SNDATA1.CIM、SNDATA2.CIM

- 0xD38 起 44 bytes 一筆，首 byte 為 0 是空位：姓 11 bytes、名 11 bytes（光榮台灣內碼），+0x21 是 u16 頭像碼（`koei_games.load_nobu3_dos_people`）。劇本 1 240 人、劇本 2 212 人。
- 組合臉的碼會撞：不同人用同一個碼（如 0x8108 松田憲秀、繁澤元氏）。所以比照 `nobu3-fc`，以「姓名＋頭像碼」去重，劇本 1 再劇本 2，共 385 人（228 組合臉、157 頭像）。0–239 和 `nobu3-fc` 相同；FC 240–255 的後來登場武將（荒木村重等）DOS 版沒有。
- 同一人同一碼、只有其中一個劇本寫錯的，取正確寫法（`NOBU3_DOS_NAME_FIX`）：齊籐朝信→齊藤朝信、羽祡秀吉→羽柴秀吉。
- `nameHistorical`（18 筆）：
  - 缺字代用：田山→畠山（義綱、義慶）、北田→北畠（具教、具房、政成）、高田定吉→高畠定吉、神原康政→榊原康政、並和康忠→垪和康忠
  - 錯字：今川氏貞→今川氏真、北庄秀綱→本庄秀綱、溫井景龍→溫井景隆、森下通興→森下通與、溥生氏鄉→蒲生氏鄉、著尾高春→箸尾高春、肉戶隆家→宍戶隆家、九鬼嘉窿→九鬼嘉隆、小早川窿景→小早川隆景、羽祡秀長→羽柴秀長
  - 不填：齊藤（齋藤）、高阪／上阪（坂）、佐佐／野野村（々）、鈴木佐大夫。

### 能力

- 同一筆人物記錄 +16 年齢、+18 政治力、+19 戦闘力、+20 魅力、+21 野望（u8），PC-98、PC-88、X68000、Win 位置都相同；忠誠度在 +31（X68000、Win 是 +34）。名稱照 MAIN.EXE 的字串「年齢 政治力 戦闘力 魅力 野望 忠誠度 兵士数 兵訓練 兵武装」（`koei_games.load_nobu3_pc98_stats`，`dekoei.py nobu-person nobu3-pc98`）。
- +17 像是死亡年齡（信玄 52、謙信 48），未確認。
- 劇本 1 是 1560 年、劇本 2 是 1582 年（檔案 +4 的 u16），兩個劇本的值不同。
- 🟡 截圖是玩家大名重骰後的值：謙信顯示 90／100／93／67，檔案是 89／100／95／67，只差幾點。

## 劇本檔的結構（SNDATA1／2.CIM）

PC-98、DOS（中文、英文）的排法相同，只有人物記錄的長度不同（PC-98 38 bytes，DOS 44 bytes，DOS 的姓名欄長 6 bytes）。FC 版的劇本資料（`famicom-re:gunyuu/docs/ROM_FORMAT.md` §2）是同一套欄位，下文的比對都對過 FC。

| 位置 | 內容 |
|---|---|
| 0x00 | 標頭：+4 年（u16，1560／1582），+12 國數（38） |
| 0x4C | 大名，46 bytes 一筆，人物指標為 0 結束（劇本 1 28 家、劇本 2 10 家） |
| 0x722 | 國，38 × 41 bytes |
| 0xD38 | 人物，PC-98 38 bytes、DOS 44 bytes 一筆（劇本 1 254 格、240 人；劇本 2 254 格、212 人） |

- 檔內的指標是載入後的位址：人物 k ＝ 0xD78 ＋ 記錄長 × k，大名 k ＝ 0x8E ＋ 46k。
- ✅ cross：DOS 中文版和 PC-98 版的人物記錄（PC-98 +16 起、DOS +22 起的 22 bytes）兩個劇本逐筆相同；國記錄除了國名與指標以外相同；大名記錄和 FC byte 相同。

## 人物欄位

PC-98 的位置（DOS 的 +16 以後各加 6）：

| 位置 | 內容 | 證據 |
|---|---|---|
| +0 | 姓 9 bytes、+9 名 7 bytes | 見上 |
| +16 | 年齢：登場那一年的年齢（開局就在的是劇本年的年齢） | ✅ cross：生年和 FC 姓名表 +14 一致 |
| +17 | 壽命：死亡時的年齢。卒年＝生年＋壽命 | ✅ cross：和 FC +16（卒年）一致，240 人全部 |
| +18–21 | 政治力、戦闘力、魅力、野望 | ✅（見「能力」） |
| +22、+23、+24 | 隱藏值 3 個，1–100 | ✅ cross：和 FC 姓名表 +17–19 相同；意義 ❌ |
| +25 | 0 | FC 武將表 +6 也是 0 |
| +26 | 登場年 − 劇本年（0 ＝開局就在） | ✅ cross：和 FC +15 一致（上杉景勝 8 → 1568） |
| +27 | 頭像碼 u16 | ✅ |
| +29 | 所在國（0 起算） | ✅ cross：FC 武將表 +7 |
| +30 | 所屬大名（大名表的序號，FF 浪人） | ✅ cross：FC +8 |
| +31 | 忠誠度（大名 100） | ✅ |
| +32 | 兵士數 ÷ 100 | ✅ cross：FC +10 |
| +33、+34 | 兵訓練、兵武装 | ✅ cross：FC +11、+12 |
| +35 | 旗標，bit 0–1 部隊（0 足軽、1 騎馬、2 鉄砲） | ✅ cross：FC +13；其他位元 ❌ |
| +36、+37 | 0 | |

- 生年＝劇本年＋(+26) − (+16)。例：北条氏直（劇本 1）+16 13、+26 15 → 1562 年生，1575 年 13 歲登場；壽命 29 → 1591 年歿。
- 🟡 +23 看起來是義理：松永久秀 4、明智光秀 64，上杉謙信 100、徳川家康 99、柴田勝家 98。沒有讀程式。+22、+24 不知道是什麼（織田信長 100／93、松永久秀 95／11）。
- 身分：大名表裡的人是大名；國記錄 +29 指的人是城主；其他有所屬大名的是家臣，FF 是浪人。遊戲裡沒有另外的身分欄。
- 一門、相性沒找到；大名之間的關係在大名表（下面）。

### 大名（0x4C 起，46 bytes）

- +0 大名本人的人物指標，+2–4 同盟大名（FF 無），+5–42 38 格關係（自己 FF；自己之後是友好度，預設 50；自己之前是 00／06 的旗標），+43–45 0。
- ✅ cross：兩個劇本都和 FC 資料 bank `+0x403` byte 相同。劇本 1：武田、北条、今川三國同盟，畠山↔六角。

## 地理

**國**（0x722 起，41 bytes）：

| 位置 | 內容 |
|---|---|
| +2 | 國名 9 bytes（PC-98 Shift-JIS、DOS 光榮台灣內碼） |
| +11 | 金、米、石高（u16）、治水（u8）、町（u16）、不明（u16，FC 畫面的扇子）、兵（u16）、民忠（u8）、城（u16） |
| +27 | 大名指標（0 ＝空白國） |
| +29 | 城主的人物指標 |
| +31 | 7 格鄰國：低 6 bits 是國號（0 起算），高 2 bits 是方向，`FF` 無 |
| +38 | 0 |

- 38 國的名字（PC-98）：越後、上野、武蔵、安房、信濃、甲斐、相模、伊豆、駿河、遠江、能登、越中、飛騨、加賀、越前、美濃、尾張、三河、近江、伊賀、伊勢志摩、山城、大和、紀伊、摂津和泉、丹波、丹後若狭、因幡但馬、播磨、出雲伯耆、三備、石見、安芸、周防長門、讃岐、阿波、伊予、土佐。
  - DOS 中文版第 29 國寫「出雲」，其他照日文字形換成繁體（武藏、飛驒、攝津和泉、丹後若狹、讚岐；安芸、伊予照錄）。
- 鄰國的高 2 bits 0–3 依序對 FC 國名表的旗標 0x80、0x40、0x20、0x10，38 國全部一致。FC 筆記推定是從哪個方向進攻的布陣區。
- ✅ cross：
  - 相鄰和國的數值都和 FC（相鄰在 bank 23 `0x2E004`，數值在資料 bank `+0x4D`）一致。
  - PC-88（0x3C 起 35 bytes 一筆，鄰國在 +29）、X68000（66 bytes 一筆）、Win（`sndata1.nb3`，64 bytes 一筆）的鄰國 7 bytes 都和 PC-98 byte 相同。
- 沒有地方的分類，劇本檔裡也沒有地圖座標。各國在大地圖上的位置在 PC-98 `MAIN.EXE` 的表裡，見下面「大地圖」。

**大地圖**（PC-98 `MAPDATA.DAT`，位址是 PC-98 `MAIN.EXE` 的映像位址，MZ 檔頭 0x3C00、DGROUP 在映像 0x202F0）：

- 4 張 416×152 的圖，壓縮法同信長4 的 `PACKDATA`（`nobu4_extras.decode_pack`），畫面逐列加倍成 416×304。第 0 張是不寫國名的全國圖，第 1–3 張是「地図切り替え」切換的東、中、西三張分區圖（有國名）。
- 色盤是數位 8 色，bit 0 藍、bit 1 綠、bit 2 紅，白是 #FFFFFF ✅ capture：分區圖 1、2、3 和 `guest os_003`、`007`、`005` 的地圖區（扣掉左上 x < 100、y < 90 的視窗）逐點相同，不含國的勢力色。全國圖 0 沒有截圖，用同一張色盤 🟡。
- 各國的點：DS:0x3C5A＋0x98 × 圖號，38 × (u16 x, u16 y)，國不在這張圖上是 FFFF；0x55B4 傳回 x 與 y × 2（加倍後的畫面座標）✅ code。分區圖上的點是替國塗勢力色的填色起點（靠近國界），全國圖上的點在國的中間。
- koei-wiki 的 `pos` 用全國圖（`world/MAPDATA-0.png`）的點：每個點都是陸地（色號 7），從各點在陸地上 4 向填色，碰不到別國的點，38 國都通過。

**戰場**（`HEXDATA.DAT`）：

- 每國一張野戰圖、一張攻城圖，各 13 × 12 格、156 bytes，同一國的兩張相鄰（野戰在前）。起點 PC-98 0x46E0、DOS 0x1A70，到檔尾為止；前面是圖塊。
- 選圖：英文版 `MAIN.EXE` 映像 0xD54（國號 < 0x26）讀 `0x1A70 ＋ 0x138 × 國號`，`[0x4EB4]` 為 1 時再加 0x9C（攻城圖），讀 0x9C bytes。✅ code。呼叫端傳的是不是被攻打的國，照 FC 的模擬器結果（第 n 張＝第 n 國）✅ cross。
- ✅ cross：76 張都和 FC（野戰 `0x2A004`、攻城 `0x2C004`）byte 相同。地形碼見 FC 筆記 §4。
- 圖塊（PC-98，位址是 PC-98 `MAIN.EXE` 的映像位址，MZ 檔頭 0x3C00）：
  - 0x1265 把整個 `HEXDATA.DAT`（0x7530 bytes）讀進 `[0x9F98]` 那段。✅ code
  - 0x0000 起是 12 個 32×32 圖示（金、兵糧、石高、治水、商業、文化、民忠、人口、城、兵士、武将、借金），每個 384 bytes。
  - 0x1200 起是 32×32 的地形圖塊，每 8 點 3 bytes（byte k＝平面 k，同 `genpei.decode_planar`），每張 0x180；0x150AD 算位址 `0x180 × n ＋ 0x1200`。✅ code
  - 0x143AC：n＝格子值 & 0xF，`[0x57D0]` 為 0（野戰）時再加 11。✅ code
  - 野戰圖的格子值有 bit 3（照 & 0xF 加 11 會畫到第 31 張以後、不是圖塊的資料），所以照 FC（bit 3 載入時另存）當成 n＝(v & 7)＋11 🟡：載入時清掉 bit 3 的程式沒找到（0xA02 的呼叫端沒追到）。
  - 奇數欄下移 16 點（同 FC），整張 416×400。
  - 攻城圖：格子值的 bit 0x10 是城內的格子（0x3X、0x79 等；0x0C–0x0F 的外圍地形沒有），畫的時候把紅色平面清掉：0x150E2 呼叫 0x13D6C（測格子的 bit 0x10），成立就把圖塊每 3 bytes 的第 2 個（平面 1＝紅）清成 0。所以城內是綠底、青色護城河，不是圖塊本身的紅黃色。✅ code ✅ capture+modified: `guest os_013.raw1.png`
    - 野戰圖也有 421 格帶 bit 0x10（值 18、19、0x2X…），但截圖裡照樣有紅色，所以匯出只在攻城圖清紅色 🟡：野戰的路徑在哪裡清掉這個 bit 沒追到（0x14710 會清 bit 0x10 並重畫，載入在 0x14876）。
    - 其他位元：bit 0x20 是城內（0x15FC2 移動消耗 0xA0、0x13F77），bit 0x40 測於 0x13DF7，bit 0x80 在 0x14246 設、0x14287 清。用途沒追。
  - 色盤：遊戲就是用 PC-98 數位 8 色（bit 0 藍、1 紅、2 綠），沒有另載類比色盤 ✅ capture: `guest os_009.raw1.png`、`guest os_013.raw1.png`。
  - 驗證：信濃（國號 4，0 起算）的兩張和截圖的地圖區（左上 416×400）逐點比對。野戰（009、010）只差左側 13 格的部隊；攻城（013）只差外圍約 50 格裡的白圈（攻方的布陣位置），其餘相同。
  - 截圖來源：使用者在 Homebrew 的 DOSBox-X（PC-98 模式）玩，Claude 收集 Ctrl+F5 存出的圖，清單見 `captures/screenshots/nobu3-pc98/index.md`。為了進到攻城戰，用記憶體 trainer 改了雙方兵數（約 00:15），所以 012、013 是 modified；009–011 在那之前。

## koei-wiki 匯出

`dekoei.py persons-export nobu3-pc98 …` 和 `places-export nobu3-pc98`（`wiki_nobu3.py`）。資料讀 PC-98 劇本，`name` 取旁邊 `../nobu3-dos` 同一格的中文名，`nameJa` 是 PC-98 的日文（不同時才填）。

- 人物 385 位，`id` 同 `build_nobu3_pc98`（劇本 1、2 依序，每個姓名＋頭像碼一人）。
  - `born`＝1560＋(+26)－(+16)。+26 在兩個劇本都是「登場年－1560」：劇本 2（1582）開局就在的人都是 22。`died`＝`born`＋寿命（+17）。`debut` 只填登場年晚於該劇本年的人。
  - `stats` 政治力、戦闘力、魅力、野望；`hidden` 寿命、義理（+23，`uncertain`）。+22、+24 沒有輸出。能力與寿命取第一次出現的劇本；劇本 2 有人不同（信長的寿命 60→70）。
  - `scenarios`：`lord` 是所屬大名本人的 id，`location` 是國號＋1；`status` 是大名（在大名表）、城主（國的城主指標）、家臣、浪人，還沒登場的寫「未登場」（這邊的寫法）。`loyalty` 是 +31。
- 地點 38 國，`id` 1–38，`adjacent` 取鄰國的低 6 bit。沒有地方。
- 大地圖：`world/MAPDATA-0.png`–`MAPDATA-3.png`（各 416×304，逐列加倍）。`pos` 是全國圖 `MAPDATA-0` 上的像素（`grid` `pixel`，w 416、h 304），取自上面「大地圖」的點表；分區圖 1–3 只附圖，`pos` 不適用。`world_check` 驗證每個點在陸地上、各在不同的國：places-export 428 checked, 0 mismatched。
- 戰場圖：每國 `field/NN.png`（野戰）、`castle/NN.png`（攻城），NN＝`id`，共 76 張 416×400，畫法見上面「戰場」。信濃的兩張和截圖相同，`battlemaps` 不再標 `uncertain`。

## 負面結論與未解

- 隱藏值 +22、+24（以及 +23 是不是義理）：只比對了數值分布和 FC，沒有找到讀它們的程式。下一步可以在英文版 `MAIN.EXE`（沒壓縮）找存取人物記憶體 +0x1E–0x20 的地方（記憶體記錄＝DOS 檔案記錄往後 2 bytes）。
- 國記錄 +20 的扇子值（u16）、人物旗標 +35 的其他位元沒解。
- 試過把三張分區圖接成一張全國圖：找不到重疊的位移，因為它們是三張各自畫的圖，不是一張大圖的三段；不用再試。
- X68000、Win 的國記錄只比對了鄰國，其他欄位沒逐欄對。

## 沒有人物使用的頭像（157–176）

- 通婚（0x114A4）：`0x9D + rand(20)`，畫面是要嫁過去的女性，group「公主」。其他畫臉的呼叫都是用人物的頭像碼。

## PC-98 版（`nobu3-pc98`）

`dekoei.py export nobu3-pc98` 用到的差異（`build_nobu3_pc98`）。來源是 `~/game-library/_original/pc98/[PC98] 信長の野望・戦国群雄伝.zip`（A、B 兩片 FDI），解到 `games/archives/pc98/disks/nobu3-pc98/A`、`B`，合併到 `games/nobu3-pc98/`。MAIN.EXE 和劇本是 1989-05-08，頭像檔 1989-02-16。B 片的 `群雄伝.DIR` 是填滿 KOEI 版權字串的檔，不是目錄。

- `MAIN.EXE` 的 header 是 0x3C00 bytes，DGROUP 在檔案 0x23EF0。下文是去掉 header 後的位址。
- 頭像：`ORGKAO1–3.DAT` 接起來是 177 張 64×80 全高（400 線）頭像，每 8 px 3 bytes，byte k＝plane k（`genpei.decode_planar`），1920 bytes，順序和 DOS 版相同。0x1DE8 起的畫圖程式把 byte 0／1／2 寫到 A800／B000／B800。
- 色盤：預設的數位 8 色。DS:0x5618 存 port A8–AE 的值 `37 15 26 04`（標準排列），0x2236 改單色，只在 0x5F5A 的閃爍特效用到，結束後還原。
- 組合臉：`MONKAO.DAT` 是 4 組零件 × 0x2D00 bytes，每組是 DOS 版那一組的全高版（位置與列數加倍）：上 36 列、下 44 列（第 36 列起），眼 10 列（第 26 列）、鼻 12 列（第 36 列）、口 18 列（第 48 列），眼鼻口 XOR 疊上（0x4594）。
  - 和 DOS 版不同，0x45B8 用頭像碼 bit 0–1 選組（`(碼 & 3) × 0x2D00`），所以 4 組都匯出成 variant。第 3 組是僧侶（下間一族等）。
- 人物：`SNDATA1.CIM`、`SNDATA2.CIM` 0xD38 起 38 bytes 一筆：姓 9 bytes、名 7 bytes（Shift-JIS），+27 是 u16 頭像碼（`koei_games.load_nobu3_pc98_people`）。人數（240、212）和頭像碼都和 DOS 版相同，去重後同樣是 385 人（228 組合臉）。日文名沒有 DOS 版的錯字，不填 `nameHistorical`。
- 通婚的公主頭像同樣是 `0x9D + rand(20)`（0x10CBE），即 157–176，group「姫」。

## X68000 版（`nobu3-x68`）

`dekoei.py export nobu3-x68` 用 `build_nobu3_pc98(x68=True)`。來源是 Internet Archive `softwarelibrary-x68k` 的 `nobunaga_no_yabou_sengoku_guny_x68k`（`~/game-library/_original/x68/ia-softwarelibrary/`，3 片 DIM），Disk A（`ORGKAO1–3.DAT`、`MONKAO.DAT`、`MAIN.Z`、`VERSION`）與 Disk C（`SNDATA1/2.CIM`）的檔案放在 `games/nobu3-x68/`。`MAIN.Z` 的版本字串是 `Rel.1A ***Feb.15, 1989***`。

- 頭像與組合臉檔和 PC-98 版逐 byte 相同。
- 色盤：`MAIN.Z`（未壓縮，檔頭 0x1C bytes）檔案 0x412D2 起的 GRB 文字色盤（每色 4 bytes）`0000 003E 07C0 07FE F800 F83E FFC0 FFFE`，各分量是 0 或最大，和 PC-98 的數位 8 色同序。
- 人物：`SNDATA1/2.CIM` 0x11F8 起 44 bytes 一筆，姓名欄同 PC-98，頭像碼是 +30 的大端序 u16（中間多了 68000 的補位）。兩個劇本的姓名與頭像碼和 PC-98 版完全相同，匯出結果除了 id、平台與色盤 id 之外一樣。kaodata 網站不另收這份資料集，只在 `nobu3-pc98` 標上 X68000 版（1989-12-08）。

## PC-88 原版（`nobu3-pc88`）

`dekoei.py export nobu3-pc88` 用到的差異（`build_nobu3_pc88`）。來源是 Neo Kobe 2016-02-25 的 `~/game-library/_original/pc88/neo-kobe-2016-02-25/Nobunaga no Yabou - Sengoku Gunyuuden/Nobunaga no Yabou - Sengoku Gunyuuden [FD].7z`。檔案放在 `games/nobu3-pc88/`：Disk C（FAT12）的 `KAODATA.DAT`，Disk A（YDOS 3.0）的 `SNDATA1/2.CIM`、`VERSION`，以及參考用的 `MAIN.COM`。

- `VERSION`：`NOBUNAGA NO YABOU -- SENGOKU GUNYUUDEN -- Rel.1C Dec.07, 1988`。這是系列的首發平台。
- `KAODATA.DAT` 和 DOS 版**逐 byte 相同**：177 張 64×40 半高頭像，加上 4 組組合臉零件。DOS 版直接沿用了 PC-88 的 200 線圖。匯出照 DOS 用 `san2_pixels`（每列重複一次）。
- 色盤：數位 8 色，色號意義同 `san2-pc88`（`SAN2_JP_PALETTE`），palette id `pc88`。
- 組合臉：`MAIN.COM` 0x2F8F 算 `(碼 & 3) × 0x1680 + 0x297C0`，用頭像碼 bit 0–1 選組（同 PC-98），所以 4 組都匯出成 variant。各區域的位置和 XOR 同 DOS（0x2F7D 是 XOR 迴圈）。
- 人物：`SNDATA1.CIM`、`SNDATA2.CIM` 0xC1E 起 36 bytes 一筆，欄位同 PC-98（姓 9、名 7，Shift-JIS，+27 頭像碼；`load_nobu3_pc98_people(..., pc88=True)`）。人數、順序、頭像碼都和 PC-98 相同，去重後 385 人。
- 姓名有 5 個 PC-88 才有的錯字，PC-98、DOS 版都已改正，填 `nameHistorical`（`NOBU3_PC88_NAME_HISTORICAL`）：
  - 河野道宣→河野通宣
  - 河野道直→河野通直
  - 萩野直正→荻野直正
  - 萩清誉→荻清誉
  - 山内隆道→山内隆通
- 公主頭像 157–176 的 group「姫」沿用 PC-98 的結論，沒有在 PC-88 程式裡另外追。

## Windows 日文版（Steam）

`dekoei.py export nobu3-win` 用到的格式（`build_nobu3_win`）。來源是 Steam 版（appid 521700，Readme 2017年2月，見 `notes/steam.md`），匯出用到的檔案複製到 `games/nobu3-win/`。

- `Nobunaga3.exe` 有 SteamStub，解法同三國志VIII（見 `notes/san8.md`）。匯出不讀 EXE。
- `Kao.nb3`、`Kao2.nb3`、`Kao3.nb3`、`palette.nb3` 都是 LS11 封裝（`ls11.ls11_decode_parts`）。頭像每段是 `2A 38`、u16 寬、u16 高，加 64×80 的 8 bit 色號，沒有壓縮。
  - `Kao.nb3`：157 張，PC-98 的頭像 0–156 重畫。
  - `Kao2.nb3`：22 張，前 20 張是 PC-98 157–176 的公主，最後 2 張是男性的臉。
  - `Kao3.nb3`：256 張，組合臉改成整張畫好的臉，沒有零件。
- 0x42A950 依頭像碼取圖：bit 15 → `Kao3[碼 & 0xFF]`，bit 11 → `Kao2[碼 & 0xFF]`，其他 → `Kao[碼]`。匯出的頭像依序是 Kao 0–156、Kao2 157–178、Kao3 179–434，`code` 就是遊戲的頭像碼。
- 婚姻（0x432DD0）的新娘臉是 `0x800 | rand(22)`，所以 Kao2 最後兩張男性的臉也會被抽到；22 張都歸 `姫`，那兩張加 `note`。
- 色盤：`palette.nb3` 第 1 段是頭像色盤（B、R、G）。頭像只用到 98 色，沒有用到色號 0 和 255，不用換色號。
- 人物：`sndata1.nb3`、`sndata2.nb3` 0x11B6 起 44 bytes 一筆（版面同 X68000 版），+30 是 little-endian 的頭像碼（`load_nobu3_pc98_people(..., win=True)`）。姓名、人數、順序都和 PC-98 相同。
  - 組合臉的碼重新編過，是 `0x8000 | Kao3 索引`，眼鼻口的位元不再使用；同一劇本裡每人一張，223 張有人用，33 張沒人用（都歸 `大眾臉`）。
  - 北条氏直在劇本 2 也改用劇本 1 的專用頭像 64（PC-98 版劇本 2 是組合臉），繁沢元氏和松田憲秀不再共用同一張臉。照 PC-98 以「姓名＋頭像碼」去重，共 384 人。
