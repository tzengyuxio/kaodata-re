# 信長の野望・覇王伝（NOBU5, PC-98 日文版）頭像相關格式

`dekoei.py export nobu5-pc98` 用到的格式。來源是 `games/archives/pc98/[PC98] 信長の野望・覇王伝o.zip`（HAO_1–4.FDI：1 システム、2 データ、3 シナリオ、4 エンディング），每片磁碟解在 `games/archives/pc98/disks/nobu5-pc98/<n>/`，合併放在 `games/nobu5-pc98/`。

## 版本

- `VERSION`：「信長の野望・覇王伝」For PC-9801 Series，Nov.30,1992 Ver. 1.1 Rel 1.1。HAO.TXT 寫 KOEI/1992。磁碟映像裡沒有保留檔案日期。
- `MAIN.EXE` 沒有壓縮（MZ 檔頭 0x6E00 bytes），DGROUP 段值 0x4AB3（DS:x ＝ 檔案 0x6E00＋0x4AB30＋x）。下文的程式位址是映像（檔案 − 0x6E00）位址。

## 頭像：KAO.NB5

- 929 張 64×80，載入在 0x351C、解碼在 0x341F。
- 索引在 `MAIN.EXE` 檔案 0x40630（段 0x390B:0x0780）：930 個 u16，單位 20 bytes，第 i 張是 `KAO[t[i]*20 : t[i+1]*20]`，最後一個 60904 × 20 正好是檔案大小。
- 每張是 u16 寬、u16 高，接著是 nibble 流（先高後低），底下是一層 byte RLE（0x3285）：`FE n` 是前一個 byte 再重複 n 次，`FE 00` 是 256 次，`FE 01` 是字面上的 0xFE。
- 每列先讀一個 mode nibble，之後逐點：
  - 沒有進行中的 run 時讀 n：n & 8 且 n & 4 → run ＝ ((n & 3) << 4)＋下一個 nibble＋6；只有 n & 8 → run ＝ (n & 3)＋2；否則 n & 7 就是色號。
  - run 進行中：mode & 8 時複製上面第 mode − 7 列同一欄，否則複製同列左邊第 mode＋1 點。
- 畫面是 3 平面（0x33A1），byte k ＝ bit k。和天翔記 KAODATA.NB6 是同一種壓縮，匯出用 `nobu_pc98_face`。
- 沒有組合臉。

## 色盤

- 頭像由 0x3675 經 0xE61 呼叫 GRPDRV 功能 0x0F（dl=1、dh=0xFF），把 E（亮度）平面填滿，所以頭像用的是色號 8–15。
- 16 色表在 `MAIN.EXE` 檔案 0x41306（段 0x3A50:0x0006），每色 B、R、G 各 4 bit（GRPDRV 功能 0x16 依序寫 port 0xAE、0xAC、0xAA）；色號 8–15 在檔案 0x4131E。季節地圖色盤（0x3A50:0x66＋0x18 × 季節）只換色號 0–7，0x3A50:0x36 是數位 8 色用的替代表。
- 頭像色（× 17）：`#000000 #0066AA #FF4422 #FFAACC #66AA44 #88DDFF #FFCC66 #FFFFFF`。

## 人物：SN1–3.NB5、S1T–S3T.NB5

- `SNn.NB5` 整檔 XOR 0xB4，載入到 DS＋0x4A（SN 0x6A9E ↔ DS:0x6AE8）。人物在 0xAE4 起，460 格 × 39 bytes，+0 不為 0 是有人：姓 7 bytes、名 7 bytes（Shift-JIS，0 補齊），+22 是 0xFF，+29 是 u16 頭像號。劇本 1–3 各 413、459、413 人。
- `SnT.NB5` 沒有 XOR，是各劇本之後登場的人物，30 bytes 一筆：+4 姓 7 bytes、+11 名 7 bytes，+26 是 u16 頭像號；檔尾有空白記錄（姓名空、頭像 0），要略過。
- 光榮外字（字形在 `KANJI.NB5`，188 字 × 16×16）只用在姓：`EC8C EC8D EC8E` 長宗我部、`EC8F EC8D EC8E` 香宗我部。
- `id`：照劇本 1、1T、2、2T、3、3T 的順序，同一頭像號只收一次（同 `nobu4-dos`），共 818 人，用到頭像 0–819 除了 139、140。
  - 同臉不同名的只有三組，都是同一人改名，比照 `nobu6-pc98` 用最通行的名字（`NOBU5_PC98_ALIASES`）：8 長尾景虎→上杉謙信、19 武田晴信→武田信玄、24 松平元康→徳川家康。
  - 同名不同臉的是不同人（河野通直兩人、風魔小太郎兩代、島津家久與後來改名家久的忠恒）。

### 能力

- 武將視窗顯示 年齢、政治、戦闘、智謀、采配、野望、気合；PK 的武将エディタ另有寿命（A 短命–D 長命）。
- PC-98 `SN` 記錄（XOR 後）+15–19 政治、戦闘、智謀、采配、野望（u8），+14 生年−1476，+28 的 bit 6–7 是寿命；`S*T` 在 +19–23、+18、+25。X68000 位置相同。Win `SV1n.N5S` 在 +0–4、+5（生年−1453）、+14，EXE 的後登場表在 +21–25、+20、+27（`koei_games.load_nobu5_pc98_stats` 等，`dekoei.py nobu-person nobu5-pc98`）。
- ✅ capture（web）：`status-screens/nobu5-pc98-web-01.png` 大友宗麟（SN1，1551）82／73／77／85／83、年齢 21，和解出值相同；`nobu5pk-win-web-01.jpg`（編輯器）織田信長 96／89／84／97／100 和 Sv11、Sv12 相同。
- PC-98、X68000、Win 三版的值相同（cross）。劇本之間略有不同（信長在 SN3 是 98／91）。
- 🟡 寿命只確認過 C；気合沒找到；PC-98 +20（Win +6）是 1–252 的不明值。
- 劇本年：SN1 1551、SN2 1568、SN3 1582（SN byte 1＋1476）；PK 的 SV10 是 1534（PC-98 PK `SN0.NB5` 檔頭）。

## 沒有人物使用的頭像

- 878–913（36 張，「姫」）：頭像號 ＝ 878＋公主表的序號（0xAB30、0xAC90、0x14F3B：(si − 0x6AE8) / 14 + 0x36E）。公主表在 DS:0x6AE8，14 bytes 一筆，名字 8 bytes 在 +8；劇本檔裡的副本（SN 0x6A9E）三個劇本相同。有名字的是 0–11：市、濃、ガラシア、茶々、豪、義、瀬名、見松院、旭、黄梅院、初、江，其餘 24 位沒有名字。
- 914–928（15 張）：西洋人、黒人等。名字從事件文字（`STR1.NB5` XOR 0xA5，0x10D01 每次讀 0x81 bytes）與 `MAIN.EXE` 的名單（商人 DS:0x88DA，傳教士 DS:0x8946，[0x89C4]）對出：917 ルイス＝フロイス、918 オルガンティーノ、919 ヴァリニャーノ（事件標題寫ヴァリニャーニ）、920 彌助（標題「黒人従者」）。925（年老的光頭日本人）、926（戴帽、有襞領的西洋人）由 0xF39B、0x10010 經 0x136C1 畫出，但沒找到名字；其他沒有找到呼叫處。匯出時 917–920、925、926 歸「事件人物」，其餘歸「不明」。
- 139、140、820–877（60 張，「不明」）：沒有人物記錄，也沒找到畫它們的程式。820–877 是一般武士的臉，像是給隨機登場的武將用的，但沒有證據。`nobu4-dos` 的 139、140 是今井宗久、千利休，這裡的 139（光頭）、140（黑帽）長相相近，但商人名單沒有對應的頭像號，所以不填。

## X68000 版（`nobu5-x68`）

`dekoei.py export nobu5-x68` 用 `build_nobu5_pc98(x68=True)`。來源是 Internet Archive `softwarelibrary-x68k` 的 `nobunaga_no_yabou_hanouden_199_x68k`（`games/archives/x68000/ia-softwarelibrary/`，System、Data、Scenario、Ending 4 片 DIM，各有一份 `[a]` 傾印，檔案相同）。System 片的 `MAIN.Z`、`VERSION`，Data 片的 `KAO.NB5`，Scenario 片的 `SN1–3.NB5`、`S1T–S3T.NB5` 放在 `games/nobu5-x68/`。`VERSION` 寫 `Mar.18,1993 Ver. 1.0 Rel 1.0`（System 片，其他片是 Mar.15,1993）。

- `KAO.NB5` 和 PC-98 版逐 byte 相同。
- `MAIN.Z` 是 CZ11 壓縮：`CONFIG.SYS` 的 `shell = \sys\ipl113.r a:open.cz a:main.z a:end.cz` 由 `SYS/IPL113.R` 解開後執行。X 檔頭 0x1C bytes 之後是 `CZ11`、u32 text 大小、u32 data 大小，+0x24 起 256 bytes 字典，+0x126 起是 LS11 的編碼（同一套前綴碼與「碼 ≥ 256 是距離、下一碼＋3 是長度」），用 `ls11.cz11_decode` 解。解開的映像從 X 檔頭的基底 0x47FFA 起算。
- 頭像索引：映像 0x5FC80 起 930 個大端序 u32，數值和 PC-98 的 u16 索引相同。
- 色盤：開機時 0x500E 把 `$A8BF0` 的 16 個 GRB 值寫進文字色盤（E82200，0xB174），色號 8–15 是頭像色。這組顏色就是 PC-98 那組 4 bit 值 v 換成 5 bit 的 2v＋1，例如 `#0066aa` 變成 `#086bad`；設計相同，只是 X68000 的量化不同。換成 8 bit 是 v << 3 | v >> 2。
- 人物：欄位同 PC-98，但沒有 XOR，而且有 68000 的補位。`SN*.NB5` 從 0xC2A 起 460 格，每格 50 bytes，頭像是 +32 的大端序 u16；`S*T.NB5` 每筆 34 bytes，頭像是 +28；公主表在 0x8D2C，每筆 18 bytes，名字在 +8。三個劇本和登場表的人與頭像都和 PC-98 版相同，只有劇本 1、2 的頭像 432 寫成「楽巌寺雅方」（PC-98 是「楽厳寺雅方」，`nobu5-pc98` 把史書寫法填進 `nameHistorical`）。

## Windows 版 with パワーアップキット（`nobu5pk-win`）

`dekoei.py export nobu5pk-win` 用 `build_nobu5pk_win`。來源是 Steam 版（appid 628090，見 `notes/steam.md`），`Kao.dll`、`Nobunaga5WPK.exe` 與 5 個劇本 `SV10.N5S`、`Sv11–13.n5s`、`SV14.N5S` 放在 `games/nobu5pk-win/`。`Nobunaga5WPK.exe` 有 SteamStub，但只加密 `.text`，`.data` 可以直接讀。

- 頭像：`Kao.dll` 的 BMP 資源（type 2）1000–2067，頭像號 n 是資源 1000＋n，64×80 8 bit 由下往上的 DIB（40 bytes 檔頭＋1024 bytes 色盤＋5120 bytes 像素，`utils.pe_resources`）。只用色號 0–7，色盤和 PC-98 版相同。0–928 和 PC-98 `KAO.NB5` 解開後逐點相同，929–1066 是 PK 新增的 138 張（標 `pk`）；資源 2067 不是臉，不收。930 和 413 是同一張圖，但分別是山名誠通（PK）和岩上朝堅用的，兩張都留。
- 劇本：`Sv11–13.n5s` 是 PC-98 的劇本 1–3（`SN1–3.NB5`，已解開 XOR），`SV10.N5S`、`SV14.N5S` 是 PK 新增的較早與較晚的劇本。人物 460 格 × 39 bytes 從 0x2AA 起（頭像 u16 在 +17，姓 9 bytes 在 +23，名 7 bytes 在 +32），公主表 36 筆 × 14 bytes 從 0x533E 起（名字 9 bytes），`koei_games.load_nobu5_win_scenario`／`load_nobu5_win_princesses`。
- 登場表在 EXE 的 `.data`（檔案 0xC3C68 起，每個劇本相隔 0x3AEC），36 bytes 一筆，byte 0 是 0 時結束（姓在 +4，名在 +13，頭像在 +28），名字可能帶全形空白，`koei_games.load_nobu5_win_arrivals`。
- 本體三個劇本與登場表的人和頭像都和 PC-98 相同，只有頭像 432 寫成「楽巌寺雅方」（PC-98 是「楽厳寺雅方」），所以這版不用填 `nameHistorical`。
- `id`：先排本體的劇本 1–3（同 PC-98 的順序，所以前 818 人和 `nobu5-pc98` 相同），再排 PK 的兩個劇本；同一頭像號只收一次。PK 劇本才有的 180 人標 `pk`。別名除了 PC-98 的三組，PK 劇本另有長井新九郎→斎藤道三、大友義鎮→大友宗麟（`NOBU5_WIN_ALIASES`）。
- PC-98 版沒人用的 820–877 是 PK 劇本的人（較早劇本的武將）用到的，所以 PC-98 的「不明」少了這 58 張。
- 沒人用的頭像：姫、事件人物同 PC-98；139、140、914–916、921–924、927、928 與 PK 的 1049–1052、1054、1055、1057–1066 歸「不明」。1057–1066 由 EXE 0x4039A0 特別檢查，呼叫處只有一個清空欄位的對話框（0x4018F0），用途沒追到。
- 頭像 0–928 放 `portraits.bin`，PK 的 929–1066 放 `extra.bin`。

## PC-98 版 パワーアップキット（`nobu5pk-pc98`，5 代的主資料集）

2026-11-07 起 5 代的主資料集（koei-wiki 的人物、地點、列伝與 kaodata）改用這一版，`nobu5pk-win` 保留。

- 來源：`games/archives/pc98/neo-kobe-2017-11-17/Koei/Nobunaga no Yabou - Haouden/Nobunaga no Yabou - Haouden (Powerup Kit) [HD].zip` 裡的 HDI。FAT12 分割區（每磁區 1024 bytes）的全部檔案取出在 `games/archives/pc98/disks/nobu5pk-pc98/hdi/`，其中 `HAOU/` 複製到 `games/nobu5pk-pc98/`。`MAIN.EXE` 日期 1993-09-03。
- 和本體的差別：多了 `KAO2.NB5`（128 張）、`KAO3.NB5`（10 張）、`BFILE.NB5`（列伝）與劇本 `SN0`／`SN4`、`S0T`／`S4T`；`KAO.NB5` 和本體 byte 相同；`MAIN.EXE`、`SN1–3`、`S1T–S3T` 不同。`NKAO.NB5` 只有開場程式 `SOPEN.EXE` 用到，格式和頭像不同，不是臉。
- 頭像：PK 的 `MAIN.EXE` 有三個索引表，`KAO.NB5` 在 0x46858（930 個 u16，929 張）、`KAO2.NB5` 在 0x46756（129 個，頭像 929–1056）、`KAO3.NB5` 在 0x46740（11 個，1057–1066），單位 20 bytes，解法同本體（`nobu_pc98_face`）。色盤在 0x4754E（本體 0x4131E）。1067 張和 `nobu5pk-win` 逐點相同 ✅ checksum。
- 劇本：配置同本體（見下一節），唯一的不同是年份改從 1453 起算（同 Win 版）：檔頭的年、人物 +14 生年、`S*T` 的 +0 登場年與 +18 生年。`SN1` 和本體比，除了這些只有頭像 432 的姓改成「楽巌寺」（本體「楽厳寺」，同 Win）；`S1T` 只差 +0、+18 ✅ code（逐 byte 比對）。5 個劇本依序是 1534、1551、1568、1582、1583 年，各 322、413、459、413、412 人，大名 51、48、43、27、30 家，後登場 418、284、133、59、53 筆。
- 國名：`MAIN.EXE` 0x603D8 起 64 個 NUL 分隔的字串（本體 0x58E78），順序同國 0–63。
- 列伝：`BFILE.NB5`（180400 bytes），1100 筆 × 164 bytes，排法和 Win 版 EXE 0x876D8 的列伝相同（u16 生年、u16 没年、160 bytes 本文），第 n 筆是頭像 n，1057 以後是空的。生没年和 Win 版 1057 筆全部相同、空的記錄也相同；本文有 477 筆不同（Win 版改寫過字句，例：頭像 4「その合理的かつ冷静」→「合理的かつ冷静な判断は」），匯出的 998 人裡 460 段不同。
- kaodata（`build_nobu5_pc98(pk=True)`）：998 人、1067 張，和 `nobu5pk-win` 比，人物（名字、頭像、`pk`）、頭像（checksum、分組、名字）0 筆不同；`pnpm verify` 2065 項 0 筆不符。
- koei-wiki（`wiki_nobu5_pc98.py`）：地點 237、人物 998，和 `nobu5pk-win` 的匯出比，除了 `dataset` 以外每一個欄位都相同（人物連 `notes` 也相同；地點只有國的 `notes` 寫國名的出處不同）。

## 劇本檔的整體配置（SN1–3.NB5，XOR 0xB4 之後）

2026-11-06 調查，給 koei-wiki 匯出人物與地理用。下面是 PC-98 版的位置；X68000、Win 版的位置不同（Win 見最後一段）。

| 位置 | 內容 |
|---|---|
| 0x0000 | 劇本號、年−1476、月（SN1 `01 4B 03`＝1551 年 3 月，SN2 1568 年 3 月，SN3 1582 年 3 月） |
| 0x0004 | 一筆蜂須賀小六的記錄，沒解 |
| 0x0024 | u32 的表，沒解 |
| 0x0122 | 大名，64 × 39 bytes（SN1 有 48 家） |
| 0x0AE4 | 人物，460 格 × 39 bytes |
| 0x50F8 | 城，173 × 38 bytes |
| 0x6A9E | 公主表（見前面「沒有人物使用的頭像」） |

- 指標是載入後的位址，減 0x40 就是檔案位置，指到人物的姓。
- 人物的「同城下一位」指標放在姓的前 2 bytes，也就是上一格的 +37；遊戲的記錄本身從姓的前 2 bytes 開始。和 `nobu4` 的排法相同。
- 照這個規則從 173 城串下去，三個劇本各 403、440、394 人的所在城、所屬大名全部對得上，0 筆不符（✅ cross）。剩下的各 10、19、19 人是浪人，不在任何城的串列裡。
- 城的順序是九州往東北：0 日之岳、1 三（城）、2 原、3 一宇治 … 101 小谷、102 清洲 … 171 三戸、172 松前。`MAIN.EXE` 0x4436 的迴圈也用 0xAD（173）當城數（✅ code）。

- 沒有讀音。
- 後登場表 `SnT.NB5`（30 bytes）：
  - +0 登場年−1476，+1 一門編號，+2 所屬大名，+3 所在城（0xFF 是未定），+4 姓、+11 名（各 7 bytes）。
  - +18 生年−1476，+19–23 五項能力，+24 義理，+25 寿命 bit 6–7，+26 u16 頭像號。
  - 例：島津歳久 `4C 06 01 07`＝1552 年、一門 6（島津）、大名 1（島津）、城 7（内）；清水宗治 `4C FF 09 31`＝大名 9（毛利）；蜂須賀小六 `41 FF FF 67`＝1541 年、浪人、城 103（鳴海，清洲旁邊）。
  - 這幾筆是看值推定的 🟡，主表的對應是 ✅。

## 地理

### 國（64 國）

國名不在劇本檔，在 `MAIN.EXE`：

- 字串在檔案 0x58E78 起，NUL 分隔、Shift-JIS。
- 指標表在 DS:0x76B4（檔案 0x58FE4），第 2–65 項依序是國 0–63（DS:x＝檔案 0x51930＋x）。
- 國 0–63 依序是：薩摩、大隅、肥前、肥後、日向、筑前対馬、筑後、豊前、豊後、長門、周防、石見、安芸、出雲隠岐、伯耆、備後、備中、備前、美作、因幡、伊予、土佐、讃岐、阿波淡路、播磨、但馬、丹後若狭、丹波、摂津、河内和泉、紀伊、山城、大和、北近江、南近江、伊賀、伊勢志摩、越前、加賀、能登、越中、飛騨、美濃、尾張、三河、遠江、駿河、南信濃、北信濃、甲斐、越後佐渡、上野、下野、武蔵、相模伊豆、上総安房、下総、常陸、陸前、陸中、陸奥、南出羽、北出羽、蝦夷。
- 有些國是兩國合成一格（筑前対馬、阿波淡路…），有些一國拆成兩格（北／南近江、南／北信濃、南／北出羽）。
- ✅ cross：島津（薩摩）、龍造寺（肥前）、相良（肥後）、宗（筑前対馬）、織田（尾張）的所在國都對得上，城的國號也和人物一致。
- 每國 1–5 城。國本身沒有記錄（金、兵等都在城上），沒找到國的相鄰表 ❌。

### 城（173 × 38 bytes，0x50F8 起）

| 位移 | 內容 | 狀態 |
|---|---|---|
| +0 | u16 城內第一位武將的指標（減 0x40） | ✅ cross |
| +2 | 城名 9 bytes（Shift-JIS，0 補齊，不含「城」字：三＝三城、原＝原城、内＝内城） | ✅ |
| +11 | 國號（0–63） | ✅ cross |
| +12 | u16 所屬大名的指標；（值−0x164）÷39 就是大名號 | ✅ cross（403 人的 +21 全部相同） |
| +14 | 0x02–0x06 與 0x80 以上，推定是城的規模或旗標 | ❌ |
| +15–16、+18–22、+24、+26、+28、+30、+32 | 數值，推定是石高、商業、兵、防御、民忠之類，沒對過畫面 | ❌ |
| +17、+23、+25、+27、+29、+31、+33–37 | 都是 0 | |

沒有讀音和相鄰關係 ❌：173 筆裡沒有和地理位置相關的欄位（每個 byte 都和城的順序做過相關性測試，最高 0.23）。城在大地圖上的格子在 `MAIN.EXE` 的另一張表，見下面「大地圖」。

### 大名（64 × 39 bytes，0x0122 起）

大名 i 本人的指標在 0x122＋39i（減 0x40 就是人物的姓）。城 +12 指的是 0x124＋39i，也就是同一筆的第 2 byte 起。其他欄位沒解。

### 地圖與戰場（🟡 code，沒畫圖）

- 地形格：
  - `MAIN.EXE` 0x653E、0x6563、0x6588 讀同一張地形格，每格 3 bytes、一列 23 格，在段 [DS:0xB920]:0x1950 起。0x653E 傳回第 0 byte，是地形種類。
  - 這張格子讀自哪個檔沒追；`M_CHIKEI.NB5`（45920 bytes）在 0x4120 開檔，推定是大地圖。
  - `H_CHIKEI.NB5`（0xE000 bytes）在 0x27AB6 整檔讀進 [DS:0xD93A]。
- 戰場圖號 DS:0x7190 的選法（0x18248 一帶）：
  - 部隊所在格的地形種類是 0x1A（城）時，由 0x18186 依城選圖。
  - 不是城的話，依第 0 byte 的值換成 0xAF 以後的共用地圖號，用到 0xAF–0xCC。
- 讀檔（0x27B11）：
  - `PACK.NB5` 讀 DS:0x7190 × 0x730。
  - `H_KPARTS.NB5` 讀 × 0x28（8400 ÷ 40＝210 筆）。
  - `H_SHIRO.NB5` 讀 × 0x73（24150 ÷ 115＝210 筆，之後依一列 23 格處理）。
  - 戰場圖共 210 號：0–172 推定對到 173 城，0xAF（175）以後是依地形的共用圖。
  - 0xAF–0xC0 這 18 號另有一張名字表（DS:0x747C，4 bytes 一筆）。
- 沒畫成 PNG，也沒確認格子的寬高。

### 大地圖（PK 的 `MAIN.EXE`）

位址是 `nobu5pk-pc98` 的 `MAIN.EXE` 映像位址（MZ 檔頭 0x7400，DGROUP 在映像 0x519A0）；本體的位址不同（上一節的 0x653E 等是本體）。

- 地形格：`M_PARTS.NB5` 開頭 0x2058 bytes 讀進 [0xCADA]:0x1950，120 欄 × 23 列，每格 3 bytes，格 (欄, 列) 在 (欄 × 23＋列) × 3（0x6EA3 一帶 `mul 0x17`）✅ code。
  - +0 地形圖塊號（0–238），+1 疊上的圖（城、港、寺…，0xFF 沒有），+2 的低 4 bit 是疊上的線形（國界、街道），0xE 是城格，0xFF 沒有；+2 的 bit 6、7 在某些顯示模式下讓圖塊號加 0x38，底圖不用。
- 圖塊：`M_CHIKEI.NB5` 讀進 [0xDB42]:0（0x4803）✅ code。
  - 0–0x599F：239 張 16×16 地形圖塊，每張 96 bytes；一列 6 bytes，先是左 8 點的平面 0、1、2，再是右 8 點。
  - 0x59A0 起：疊上的圖，每張 128 bytes（96 bytes 圖，0x60 起 32 bytes 遮罩，先 AND 遮罩再 OR 圖，0x6FEA）。
  - 0xAFA0 起：線形，每個 64 bytes（32 bytes 形狀、32 bytes 遮罩），地形圖塊號 < 0x5F 時畫色號 7，否則色號 2（0x7024）。
- 位置：格 (欄, 列) 畫在 (欄 × 16, 列 × 16，奇數欄再往下 8)（0x6F16），整張 1920×376。
- 城的格子：映像 0x43870＋0x114 起 173 × (欄, 列) 兩個 byte，第 k 筆是城 k（0x6F49 用它找城）✅ code。173 格都是城格（+2 低 4 bit 0xE），也剛好是地形格上全部的城格；每國的城都聚在一起（同國的城在欄或列上最遠相隔 14 格），城 0 日之岳在最西、城 172 松前在最東。
- 色盤：色號 0–7 是季節表（`MAIN.EXE` 檔案 0x47596＋0x18 × 季節，B、R、G 各 4 bit，同「色盤」一節本體的 0x3A50:0x66）。第 0 組當成春：第 2 組偏紅褐（秋）、第 3 組偏灰白（冬），第 0、1 組哪個是春沒確認【推】。沒有 PC-98 截圖，色盤只讀程式的表 🟡 code。
- Win 版 `Map.dll` 101–104（1920×376）同樣大小，但是重畫的圖，沒拿來比對。

### 家宝

- 名稱：EXE 檔案 0xB9C30 的 u32 指標表，120 項。順序和 PC-98 `KAN.NB5` 0xB7A 起的名稱表（11 bytes 一筆，接在官位名後面）完全相同，120 筆逐字相同（✅ cross）。
- 數值：劇本檔 `SVnn.N5S` 0x6EE4 起 120 × 4 bytes，緊接在城表後面，5 個劇本逐 byte 相同。
  - +0 u16 持有者：5 個劇本全是 0xFFFF，也就是開局時沒有人持有家宝（✅ data）。PC-98 人物 +35 bit 7 的 18 人（松永久秀、本城常光、馬場信房…）不是家宝持有者，舊筆記的推測不成立。
  - +2 價值：15–250（九十九茄子、平蜘蛛茶釜、蘭奢待、地球儀等 250）。推定是褒美時的分量，沒追程式 🟡。
  - +3 低 5 bit 是圖號（0–25）；bit 6 只有蘭奢待、地球儀（都是事件取得的），bit 7 是自鳴鐘以後的 20 件南蛮物，意思都是推的 🟡。
- 類別：EXE 0xD669C 的 6 個名稱（茶器、武器、舶来、絵画、書籍、財宝），0xD66B4 的 26 bytes 把圖號對到類別：0–4 茶器、5–9 武器、10–14 舶来、15–18 絵画、19–23 書籍、24–25 財宝。照這張表分出來是茶器 49、舶来 20、武器 17、絵画 16、書籍 15、財宝 3，和名稱都吻合（聖書在書籍，南蛮様鉄兜在舶来，甲州金在財宝）✅ cross。類別表在哪裡被用到沒追（`.text` 加密）。
- 圖：EXE 的 BMP 資源 201–226 是 26 種家宝圖（64×45，256 色），圖號 k 是資源 201＋k；200 是 24×24 的小圖示。PC-98 `ITEM.NB5`（28080 bytes）是同樣 26 張，64×45、3bpp、byte 交錯（同 `utils.to_3bpp_indexes`），每張 1080 bytes，內容和 Win 版逐張同一題材、重畫成 256 色（✅ cross，看圖）。PC-98 用頭像的色號 8–15 上色，看起來合理，但沒找到程式依據 🟡。

- 靜止圖只有 `gaiko.dll` 的 101–104（320×240 全彩，外交・謁見的場景）和 EXE 資源 153（640×480，持槍武士的畫，用途不明）🟡。
- PC-98 的事件圖沒有匯出：
  - `END.DAT` 第 0 張（640×200）、`PACK.NB5` 第 0 張（640×280，謁見場景）是 `u16 寬、u16 高`＋3 bit RLE（同 `genpei.read_rle3`），解得出來，但色盤在程式裡，沒找到 🟡。`END.DAT` 第 1 張（125×247）之後、`PACK.NB5` 0x71CC 之後不是同一格式。
  - `ANIME.NB5`、`FUJIN.NB5`、`JISIN.NB5` 沒解 ❌。

### 家紋、大地圖

- `Kamon.dll` 的 BMP 200–305，106 個家紋，輸出成 `kamon/000`–`105.png`（資源號 − 200）。和大名、一門的對應沒找 ❌。
- `Map.dll` 101–104 是 1920×376 的大地圖，四張的地面色不同：3 是秋、4 是冬（看圖 ✅），1、2 是春、夏哪一張沒確定 🟡。120 是「戦国大名割拠図」（512×256）。106 是 KOEI 標誌，不收。`Hexmap.dll`（206 張，48 MB）是戰場圖，`Unit.dll`（434 張）是部隊圖塊，都不在這一節。

### 事件文字

- 事件寫在加密的 `.text` 裡，沒辦法照事件切。匯出 `.rdata` 裡所有日文字串（1923 則），每則記下檔案位置，以及 `.data` 裡引用它的指標表（連續的字串指標當成一張表）和序號。
- 主要的表：0xB8C58（250 則，本能寺、山崎、伊達輝宗遭擄、佐々木小次郎與宮本武蔵、山内一豊の妻、姫的婚禮等事件的台詞與旁白）、0xBA110（294 則，論功行賞與家臣的話）、0xB9858（523 則，官位、國名、家宝名等名稱）、0xB7720／0xB7778／0xB7B58（豐凶、雪、台風的通知）、0xBA088（15 個合戰名）。不在任何表裡、只從程式引用的有 676 則，多半是調略、合戰的短訊息。
- 事件的觸發條件、事件與台詞的對應都沒有解 ❌。PC-98 的 `STR1.NB5`（XOR 0xA5，開頭 36 bytes 沒解）、`STR2.NB5` 是同樣的事件文字，夾著非文字的資料，沒有拿來比對。
