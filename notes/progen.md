# プロジェネター（PROGEN, PC-98）頭像相關格式

`dekoei.py export progen-pc98` 用到的格式。來源是 `games/archives/pc98/[PC98] [光栄] プロジェネター（FDI).zip`（5 片 FDI，`disk.txt` 標 1995-08-22），每片解到 `games/archives/pc98/disks/progen-pc98/disk1..5/`，合併到 `games/progen-pc98/`（disk4／5 重複的 `PUT.DAT`、`SHELL.SYS` 不覆蓋）。

- `MAIN.EXE` 是 MZ，header 0x4400 bytes；DGROUP 是段 0x341F（檔案 0x4400＋0x341F0）。下文的「DS」是 DGROUP 內的位移，程式位址是去掉 header 後的 image 位址。

## KAO.LZW：頭像與組合臉零件

- 前段是 LS11，125 段，每段 1920 bytes＝64×80 3 bpp。
  - 排法是逐列交錯：第 r 列在 r×24，平面 q（0–2）在 +q×8，每平面 8 bytes，MSB 是最左邊的點；平面 q＝色號 bit q。
  - 0xD03C 讀一段（0x780 bytes）後以 GRCG 3 平面模式畫出，所以只用色號 0–7。
- LS11 之後是組合臉零件，不壓縮，0xCF6A 直接從檔案位移讀：
  - 頭像碼 bit 15–14 是 2 時讀 0x3A423 那組，否則讀 0x36FA3 那組（各 0x3480 bytes，第二組剛好到檔尾）。
  - 每組 4 層 × 4 個零件，每個零件是「列數 ×（3 平面 × 寬 bytes）」，依序 OR 進清空的 64×80 緩衝區：

    | 層 | 碼的位元 | 寬 × 高 | 位置 |
    |---|---|---|---|
    | 頭盔上 | 1–0 | 64×40 | 第 0 列 |
    | 頭盔下（含身體） | 3–2 | 64×40 | 第 40 列 |
    | 眼 | 5–4 | 48×32 | 第 16 列 |
    | 口 | 7–6 | 48×48 | 第一組第 32 列、第二組第 16 列 |

  - 眼、口都靠左（x＝0）。

## 色盤

- 0x8B8A 把 DS 0x67BA 的 8 色設成色號 0–7（色號 8–15 是 DS 0x67CA 起的場景色，頭像用不到）。
- 每色一個 word：bit 0–3 是 B、4–7 是 R、8–11 是 G（0x39BD 寫 I/O port 0xAE／0xAC／0xAA），匯出時 ×17。

## 人物與頭像碼

- DS 0x33E4 的人物表（0xA95A）：100 筆 × 33 bytes，+0 u16 頭像碼、+2 u8、+3 Shift-JIS 名字（NUL 結尾）。最後三筆是「リザーブ１」–「リザーブ３」，不匯出。
- 0xD088 畫頭像：碼的 bit 15–14 是 0 時是 KAO.LZW 的第 n 張，否則是組合臉（bit 13–8 不看）。
  - 碼 0xFFFF 也照組合臉畫；沒有對象時（0x1D3D7、0x202B2）就是傳 0xFFFF。テオリカス 的碼是 0xFFFF。
  - 0xAC60 在產生新船員時檢查組合臉碼不和人物表、船員表（DS 0xA8A4，5 筆）重複，所以船員的臉是隨機組合的。
- 沒有人物記錄的頭像：
  - 對話框 0xD1D2 以 ax 為頭像碼。寫死的碼有 0x53（機器人）、0x61、0x6B–0x75；DS 0x7968 是 10 個設施的頭像表（0x6B、0x6C、0x70、0x6E、0x6F、0x6D、0x73、0x74、0x72、0x75）。這 12 張歸「設施人物」（店員、酒保、UCPO 中心等）。
  - `EVENT.EVT` 的文字整段 XOR 0x77；正文是全形字，半形大寫字母是控制碼（0x1AD5B 的跳躍表從 `C` 到 `Z`）：`K<n>` 顯示人物 n 的頭像、`O<n>` 直接指定頭像碼、`P<n>` 是人物 n 的名字。只出現在 `O<n>` 的頭像歸「事件人物」，其中不少是主要人物的表情變化。
  - 72、106 在程式和事件裡都找不到，歸「未使用」。

## 匯出

- 97 人：71 人用 KAO.LZW 的頭像，26 人是組合臉。
- 組合臉的 variant 1–3 對應碼的 bit 15–14，variant 3 和 1 用同一組零件。眼、口用 `blend: "or"`。
- 名字照遊戲寫法（含全形英數，如 `Ｄｒ．Ｋ`）。
