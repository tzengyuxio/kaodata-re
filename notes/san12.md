# 三國志12 with パワーアップキット（SAN12PK, Steam 日文版）頭像與人物格式

已匯出成 `san12pk-win`（2026-10-16；2026-10-19 改成從 360×512 裁出的 96×120）。來源是 Steam 628080（`games/steam/628080/`）。

## 頭像：Data/KAO_*.S12

- `KAODATA.S12`：`S12.` 檔頭，+4 u32 資料大小 254，+8 u32 2000，0xC 起 250 bytes 是 2000 個頭像號的有無位元表（高位元在前），699 個＝本體 695 張加 800–803。
- `KAO_W_L`／`KAO_W_S`／`KAO_F_M`／`KAO_F_S.S12` 是同一組 2000 項、四種尺寸，`LINK` 封裝（同天道的 `KAO_M.N13`）：
  - +4 u32 項數 2000。
  - +0x10 u32 矩形表位置（0x3EA0），每項 12 bytes：u16 x、y、寬、高。
  - 0x20 起每項 (u32 位置, u32 大小)。
- 每項是 `GT1G0500` 貼圖：+0x26 的高低 nibble 是 log2 高、寬，+0x2C 起是 B、G、R、A。空號是 1×1。

| ---- | -------- | ---- |
| KAO_W_L | 360×512 | 512×512 |
| KAO_W_S | 90×128 | 128×128 |
| KAO_F_M | 48×60 | 64×64 |
| KAO_F_S | 32×32 | 32×32 |

- 依「不小於 64×80、最接近」的規則是 `KAO_W_S` 的 90×128，但使用者決定改收 `KAO_F_M` 的 48×60（2026-10-16）。933 張都有 48×60 版；每張最多 2819 色、alpha 全是 255，所以仍匯出成全彩。
- 本體有 695 張。追加臉另有一份 `.dat`（u32 個數＋頭像號），圖檔排法相同：
  - `AddKao00/ADD00.dat`：800–803。
  - `PK/AddKao20/ADD20.dat`：180 張，補 PK 才有臉的人，如 99、129、185。
  - `PK/AddKao21/ADD21.dat`：1128–1146。
  - `PK/AddKao21/SP0.dat`：1150–1184。

### 48×60 在 360×512 上的裁切位置（2026-10-19）

kaodata 想要比 48×60 大的頭像，所以用 `KAO_F_M` 反推它在 `KAO_W_L` 上的框（腳本與 933 張的框在 `research/face-crop/`）：把大圖縮小後和小圖做模板比對（以大圖的 alpha 加權，FFT 掃倍率，再用 Nelder-Mead 細調 x、y、倍率，雙三次取樣）。

- `KAO_W_L` 的 alpha 把背景去掉了（邊緣有淡出），但 alpha 0 底下的 RGB 還留著完整的背景畫面；`KAO_W_S`、`KAO_F_M`、`KAO_F_S` 有畫好的背景。`W_S` 的人物比 `F_M` 小很多，`F_M` 不是由它縮出來的。
- 933 張全部對上：RMSE（0–255）中位數 10.7、95% 在 17 以內，框都在 360×512 之內。殘差主要來自小圖自己的背景。
- **每張一個框**：框是 4:5（48×60 的倍數），寬 70.8–198.8 px（中位數 114.8），位置也各不相同，沒有固定的裁切方式。所以照這些框從 `W_L` 裁，就能精確重現遊戲的 48×60 構圖。
  - 比對時要允許框超出人物、延伸到透明背景（覆蓋率門檻 0.6）；門檻 0.85 會讓約四分之一的臉找錯位置。
  - 寬度不到 96 px 的框有 89 張，做 96×120 時這些要放大；64×80 都不必放大。
- 小圖另外修過的：23 號的 48×60 把畫過臉的長槍拿掉了，912 號拿掉了手和筆。RMSE 20 以上的 34 張多半是 1110–1139 一類的漫畫風臉，框的位置是對的，差在小圖有黃色等底色。
- 遊戲沒有裁切表：LINK 的矩形表只是貼圖裡的位置。說明書的「新武将登録」、「武将編集」也只能從既有的臉挑，沒有匯入圖片的功能。
- 裁的時候不要 alpha、只取 RGB，背景就和 48×60 一樣是畫好的（`research/face-crop/samples.py`）。
- **4:5 裁切規則（使用者 2026-10-19 決定改收 96×120，kaodata 凡例引用這裡）**：每張頭像用它自己 48×60 在 `KAO_W_L` 上的框 (x, y, w, h)（`research/face-crop/data/san12_boxes.json`），不加調整，只取 RGB，用 Lanczos 縮放成 96×120。依據：
  - 框是遊戲自己的 48×60 構圖，本來就是 4:5，不必再定下緣（和三國志13 不同）；933 張全部推得出框、都在 360×512 之內，沒有例外。
  - 框寬中位數 114.8 px，大多是縮小；寬不到 96 px 的 89 張是放大（最小 70.8 px，放大 1.36 倍）。
  - 框寬的分布（933 張）：最小 70.8、5% 92、25% 105、中位數 115、75% 125、95% 157、最大 198.8 px；不到 96 px 的 89 張、96–120 的 498 張、120–144 的 252 張、144 以上的 94 張，高度都是寬的 1.25 倍。各編號區段都有窄框，不集中在某一類。
  - 框寬差這麼多，是因為 360×512 是半身到全身的立繪，頭在畫面裡畫多大每張不同；框只是 48×60 涵蓋的臉部那一塊，不是整張圖。例如最窄的 1101 是騎馬持刀的全身像，頭只占上方一小塊，框是 70.8×88.4（遊戲的 48×60 是把這塊縮小約 1.47 倍）。
  - 遊戲本身的尺寸是 360×512（`W_L`，去背）、90×128（`W_S`）、48×60（`F_M`）、32×32（`F_S`），96×120 是本站裁的，遊戲裡沒有。
- 逐張無損 WebP 的估計（30 張平均，Lanczos 縮小，不透明，參數同匯出：lossless、quality 100、method 6、exact）：64×80 約 8.0 KB／張、933 張約 7.3 MB；96×120 約 16 KB／張、約 14.6 MB。現在的 48×60 實際是 4.5 MB（平均 4.9 KB；`du` 因為磁碟區塊會顯示 7.3 MB）。都是檔案位元組的合計，不含約 130 KB 的 `dataset.json`。

## 劇本：Scenario/、PK/Scenario/Scenario*.dat

- `ILNK` 封裝：+4 u32 段數，+8 起是各段的位置。
- 第 0 段是明文，其餘各段用同一個種子 0xE0A 加密，整段一次解：
  - 解密函式是 `San12WPK.exe` 0x5F8D90（`.text` 被 SteamStub 3.1 加密）。AES 金鑰、IV 和被搬走的 16 bytes 在 bind 標頭（EP − 0xF0，依 SteamXor 解開）+84 起，IV 先用 AES-ECB 解，`.text` 再用 AES-256-CBC 解。
  - 亂數是 `s = s * 0x6C078965 + 0x3039`，取 `s >> 16`。
  - 剩 2 bytes 以上時先取一個亂數：奇數就再取一個，和下 2 bytes 做 word XOR；偶數（或只剩 1 byte）就再取一個 r，該 byte XOR `(r >> 8) ^ r` 的低 8 位。
- 人物段：PK 劇本是 438000 bytes（1500 筆 × 292 bytes），本體 396000 bytes。
  - 記錄是位元欄位，+0 的 11 bit 是人物號。
  - +4 名（5 bytes）、+9 姓（5 bytes）、+0xE 讀音（半形片假名，姓名連寫），Shift-JIS。外字在 U+E000 起，例如「公孫」。
  - 未用的位元常留有雜值。
- 頭像號是記錄 bit 482 起的 11 bit（+0x3C 的 bit 2 起），本體劇本（264 bytes 一筆）也在同一位置。頭像號和人物號無關，例如關羽 67→2、呂布 437→3、貂蝉 824→566。
- Scenario0（總表）830 人有名字，用到 793 張臉；夏侯惇在劇本 1、2、3、9、12、20 改用 1100（雙眼完好的臉），合計用到 794 張，933 張中 139 張沒用到：1101–1139、1142–1146、1150–1184（無雙聯動）、1266–1279、1600–1609、1900–1935（PK 新加的汎用臉，應是給新武將用）。
  - 0–548、800–831（女性）、900–964（信長的野望）、1150–1191、1225–1231（古代人物）、1298–1306 每人一張臉。
  - 汎用臉：1350–1409 的 60 個職稱人物（文官、兵士、山賊將等）共用 1000–1022 的 23 張（13 張被多人共用，共 50 人）；1410–1475 的「〇〇の父」等 66 人各用 1200–1265 一張。
- 外字（U+E000 起，即 SJIS F040 起）照讀音與史書推定：E000 瓚、E003 郃、E004 蒯、E006 傕、E009 詡、E00C 龐、E00D 繇、E00E 邈、E00F 騭、E011 闞、E012 玠、E014 邢、E015 歆、E016 闓、E018 譙、E019 琬、E01A 郝、E01D 褚、E025 璝、E032 綝、E037 笮、E038 祜、E039 蕤、E03B 毌、E03D 瓘、E03F 琰、E043 龔（龔都；鞏志用 JIS 本來就有的「鞏」E8DD，JIS X 0208 沒有「龔」，2026-11-02 改正，原本誤推為鞏）、E044 眭、E04F 宓、E051 禕、E056 蹋、E05A 氐、E062 臏、E063 淩、E064 嬴、E065 璜、E06F 罃、E0D4 嬀（嬀覽，緊接戴員）。字型 `font/F_FONTJ.s12`（u32 字數 7832＋SJIS 碼表，F040–FC4B 共 509 個外字）的點陣還沒解，沒有用圖對過。
- Steam 檔裡沒有中文名（Big5、UTF-16、UTF-8 都搜不到「劉備」），只有日文。
- `PK/Msg/S12MSG03.s12` 是列伝（1089 則，順序同人物號）。繁中版（depot 628082）只有 938 則，依 id 範圍緊排：0–749 同號、800–831 減 50、900–964 減 111、1150–1231 減 296、1300–1306 減 518（`san12_extras.BIO_RANGES`，照內容判定 🟡 cross：貂蝉 824→774、織田信長 900→789、項籍 1157→861）；549–749、896–928 是空的，936、937 不是文字。格式同三國志11 繁中版。名字在繁中劇本的人物記錄（姓 +9、名 +4，cp950），外字另有 FA70 坂、FA7F 琰。koei-wiki 匯出（2026-11-10，`dekoei.py biography <dataset> --game-dir ../games/steam/<appid>-tchinese/depot --out ../export/koei-wiki/<dataset>.jsonl`，總表在 `notes/san-biographies.md`） 702 人。這個檔沒有壓縮：u16 個數，接著是 u32 的位置表（格式見「事件、插圖、道具」的訊息檔一節）。

### koei-wiki 匯出：人物（2026-11-11）

`dekoei/wiki_san12.py` 的 `persons(game_dir)` 寫 `export/koei-wiki/persons/san12pk-win.jsonl`（koei-persons/1，770 人，`id` 同 kaodata `san12pk-win` 與能力值匯出）；`scenarios_csv` 寫 `games/san12pk-win/extract/tables/scenarios.csv`（17 個劇本的編號、檔名、日文與繁中標題、年份、君主）。`persons_export.check` 9841 項、koei-wiki `verify_persons.py` 32065 項，都 0 問題。欄位名照繁中版 `San12WPK.exe` 0x1a57b2c–0x1a57c8c 的倒序欄位名清單（所屬勢力 基礎忠誠 位階 相性武將 軍團長 … 義兄 勇猛 死因 卒年 生年 登場年 性別 血緣 所在都市）。

- **收哪些人**：同 kaodata，Scenario0 有名字的 830 槽去掉 60 個職稱槽（文官、兵士、山賊将…，臉 1000–1022），770 人；職稱槽不當人物，不出。「〇〇の父」等 66 人沒有生年、能力與讀音，只當親屬被引用（`notes` 有寫）。
- **劇本段的種類**：第 0 段是各段的種類號（u32）。0x95 標頭 668、0x82 都市 40×248、0x85 勢力 40×84、0x87 軍團 40×800、0x92 人物 1500×292、0x8F 名品 300×76；0x86、0x88、0x89、0x8D、0xAA、0xB8、0xB9、0xBD（劇本 2 另有 0xBB）沒解。
- **劇本編號**：標頭 +0 的 byte，等於檔名的號碼：1–15、20、21，共 17 個；Scenario0 是總表，不是可選的劇本。PK 的這一組已包含本體的劇本，所以只用 PK 的。選單順序沒有截圖確認，照編號排（🟡）。年份是標頭 u32 的 bit 12 起 10 bit，有號數（戦国七雄 −246）；標題是 +4 起 21 bytes（日文 cp932，繁中 depot 的同名檔 cp950）。
- **姓名**：`name` 取繁中劇本的人物記錄（`san12_extras.bio_names`），日文不同時放 `nameJa`（187 人）；`reading` 是日文讀音轉平假名。沒有字。
- **固定值取 Scenario0**：能力 +68–71、特技 +0x4C 起 20 個 u32 旗標、兵科 +0x48 低 2 bit、性別 bit 480（1＝女）、生年 bit 512、登場年 bit 522、没年 bit 532（各 10 bit）、相性 bit 1263（8 bit）、義理 bit 1813（3 bit），見 `notes/san-attributes.md`。戦法 +0x49 只有編號，名稱表沒接，沒出。死因 bit 542 寬度不明，沒出。
- **relations**（u32 對齊的 11 bit 人物號，2047＝沒有）：
  - bit 1280（+0xA0）血緣：一門之首的人物號（曹丕、曹植→曹操，袁紹→自己），放 `clan`。
  - bit 1292 父親：「〇〇の父」44 人裡 39 人對上（袁紹→袁紹の父、曹操→曹操の父、諸葛亮→諸葛亮父），劉禅→劉備、関平→関羽、馬超→馬騰，✅ cross。`children` 由父親與母親反推。
  - bit 1312（+0xA4）母親（曹丕、曹植→卞氏，孫尚香→呉国太；孫権沒填），🟡。`siblings` 是父親或母親相同的人。
  - +0xA8、+0xAC、+0xB0 配偶（劉備→甘氏 糜氏 孫尚香），單方面寫的也互補。
  - bit 1440（+0xB4）義兄：義兄弟的長兄，長兄指自己（劉備、関羽、張飛都是 417），同一長兄的人互為 `sworn`。
  - 親愛武將 +0xB8 起 4 個、厭惡武將 +0xCC 起 4 個（u32 間隔）：koei-persons/1 沒有對應的鍵，寫在 `notes`。
- **scenarios**（每個劇本自己的人物記錄）：
  - 所在都市 bit 1873（6 bit，63＝不在這個劇本）：63 的不列（已死或是別的劇本的人，例如反董卓連合的信長們）。值是都市號＝places 的 id。
  - 所屬勢力 bit 1866（6 bit，63＝沒有）：勢力段 0x85 第 n 筆的 bit 14 起 11 bit 是君主。17 個劇本每個有人的勢力都有君主、君主都屬於自己的勢力（信長転生的勢力 32–34 需要 6 bit，所以不是 5 bit）。
  - `status`：遊戲的身分詞（繁中 EXE 0x1a55e00 起：太守 都督 軍師 君主 死亡 俘虜 一般 在野 未發現 未登場）。君主＝勢力段的君主；都督＝軍團段 0x87 bit 7 起 11 bit 的軍團長（開局的軍團長都是君主，所以沒有出現）；太守＝都市段 bit 967 起 11 bit（劇本 2、5 對上所在都市與所屬勢力）；其餘有勢力的是一般。沒勢力的：該劇本的登場年 ≤ 劇本年是在野，否則未登場（帶 `debut`）。軍師、俘虜的欄位沒找到，軍師會被寫成一般（🟡）。
  - `loyalty` 是 bit 1824 的 byte（君主 100，一般多半 100），只給君主以外有勢力的人；有 110、120、150、200、255（關羽、張飛在劉備下是 255），照原樣輸出，意思沒查（可能是「基礎忠誠」）。
  - 戦国七雄（劇本 11，−246）也有曹丕、孫堅、趙雲等三國武將在七國之下，照資料輸出。
- 🟡 的欄位都列在 `uncertain`：性別、兵科、特技、died、debut、hidden.*、relations 的 mother／spouse／sworn／clan／siblings、scenarios 的 status／location／loyalty。

未解：戦法名稱表、死因寬度、軍師與俘虜的身分欄位、忠誠超過 100 的意思、bit 1872 與 +0xE4（bit 1856）的 byte（在勢力的人是 150–190 的值）、勢力段與軍團段的其他欄位。

### 名品：PK `Scenario0.dat` 第 27 段（本體第 17 段）

- 300 筆 × 76 bytes（本體 60 bytes），名稱有的是 0–204（本體 0–183；PK 加 184–204，標 `pk`）。+4 名稱，+0x11 讀音（半形片假名）。
- u16 +0x30：bit 0–5 種類，6–7 能力（0 統率、1 武力、2 知力、3 政治），8–9 效果種類，10–15 數值。效果種類 0 是加能力（武器 1 武力、兵法書 0 統率、経書 2 知力、史書 3 政治，和名稱吻合，✅ cross）；1 是別的效果（馬、薬、医書、玉璽；壮健水的說明是延壽，🟡）；3 是沒有能力效果（宝物）。`items.csv` 的 `stat` 只在效果種類 0 時填，`effect` 是原始的 4 bit。
- u16 +0x32 bit 5–9 是特技號（31＝沒有），對到第 41 段的特技表（136 bytes × 20，+4 名稱，+9 讀音，+16 說明）：赤兎馬→神速、斬蛇の剣→豪傑、李広の弓→遠射、算盤→商才，✅ cross（名稱與效果吻合）。
- +0x34 是價值（赤兎馬 60、玉璽 100，🟡 用途）。u16 +0x3A >> 6 是圖號：0–178 是 `Data/ITEM_STL.S12`（LINK，179 張 GT1G0500，256×256 貼圖裁 240×240），179–199 是 `resfiles_additem20_pk.bin`（外層 LINK 一項，裡面 0x18 起是同格式的 LINK）。薬 5 種共用一張圖（113）。

- 說明是 `PK/Msg/S12MSG04.s12` 的第 id 則（0 赤兎馬、198 蒺藜棒…都對得上，✅）。外字 E059 依讀音是「蒺」。

- 各劇本的持有者（2026-11-11 找到，`items_export.items_san12pk_win`）：每個 `PK/Scenario/ScenarioN.dat` 的名品段（0x8F）同樣 76 bytes 一筆，bit 448–458（+0x38 起 11 bit）是持有者的人物號，0x7FF 沒有 ✅ cross（赤兎馬：184 董卓、190 與 195 呂布，青龍偃月刀 関羽，三尖刀 紀霊）。持有者常是當年還沒登場或已死的人（184 年的白龍＝趙雲、四輪車＝諸葛亮），寶物匯出只留在場的人：846 筆去掉 324 筆。

### 訊息檔：`PK/Msg/S12MSG0?.s12`

- u16 則數，接著每則一個 little-endian u32 位置。
- 文字是 Shift-JIS，但半形假名預設是平假名，`1B 4B`（ESC K）之後是片假名，`1B 48`（ESC H）切回。`02 96 <數字> x` 是顏色（1 人名、6 地名），`02 97 68`…`02 97 7A` 夾著讀音，`0A` 換行，`05` 補白。其他 0x00–0x1F 是變數與指令，`script.jsonl` 原樣留成 `{xx}`。
- 00 是各種口吻的語尾，01 是介面訊息，02 是戰略事件與交涉台詞，03 是列傳，04 是名品說明與用語說明，05 是事件腳本。
- `S12MSG05`：第 0 則「Start of script voice message.」，1–520 有語音，521 結束，522「Begin of script message.」，523–2973 沒有語音，2974 結束。1–520 依序對到 `SND/voice/Strategy/EV*.g1l` 排序後的 520 個檔，事件邊界和內容吻合（桃園、連環計、官渡、三顧、赤壁等，✅ cross）。說話者不在訊息檔裡。
